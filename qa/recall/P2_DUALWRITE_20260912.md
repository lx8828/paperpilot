# P2 双写（摘要嵌入 + 原表 BM25）—— **负结果，已收口**（2026-09-12）

> **结论先行**：两次尝试（短摘要 v1、保留数值的摘要 v2）都**没有超过现状**，
> 且 v2 只是"接近中性"（并集增益 19→17/22）。根因是**单篇检索靠同篇区分度**（§3、§5）。
> **决定：不再投入表块向量侧，代码保留但默认关。**

> 计划出处：`TABLE_FEED_20260912.md` §110「P2 双写：表块产出『规范 markdown（作答）+
> 一行语义摘要（嵌入）』，检索用摘要向量 + 原表 BM25」。
> 复算：`_p2_mech.py`（机制）、`_union_prod_eval.py`（两臂，`PP_OUT` / `PAPERPILOT_CHUNK_VIEW_DIR` 分离缓存）。

## 3. 机制验证（`_p2_mech.py`，直接用两臂的向量缓存）

| 指标 | 原表向量 | 摘要向量 | 判定 |
|---|---|---|---|
| 同篇 **表块间平均余弦** | 0.593 | **0.616**（**16/22 篇变高**） | 摘要让同篇表块**互相更像** → 区分度下降 |
| 目标表 vs 其它表块的**向量 margin** | 中位 **+0.033** | 中位 **+0.018** | **17 题变差 / 5 题变好** |

**机制**：我们的检索是**单篇内**在 10~40 张表里做**区分**。原表 markdown 虽然"不语义"，
但**极其特异**（每个数值/标签都不同）——这正是把目标表从同篇兄弟表里分出来的东西。
摘要由"标题 + 列名 + 首列实体名"组成，而这些成分在**同一篇的表之间高度重合**
（同论文的表常共享 caption 模板、列名、语言/模型名）→ 向量被"平均化"→ 目标失去优势。

### 与既往结果同源（一条统一的规律）

- 给表块加 **150 字通用填充** → 向量净 3 题变差（`EXT_REPR_20260911.md`）；
- 给表块加 **refs 全量**（相关正文）→ 向量净 7 题变差（同上）；
- 把表块换成**语义摘要** → 本次，位次中位 +0.5、并集增益 −2。

三次都是同一件事：**单篇检索的约束是"同篇内区分度"，不是"语义友好度"**。
任何让表块向量**向同篇其它表靠拢**的操作（加通用文字、加同域散文、换短摘要）都会变差。

## 4. 状态与后续

- **代码保留、默认关**（`PAPERPILOT_TABLE_EMBED_SUMMARY=1` 才启用）；线上行为不变。
  `embed_text` 机制本身是有价值的基建（任何"嵌入文本 ≠ 作答文本"的实验都能复用）。
- 若要继续，按"直接针对已诊断的病因"排序：
  1. **保留特异性的摘要**：摘要里带上**关键行的取值样本**（如 `English: Acc 0.71 / F1 0.68`），
     即"自然语言但保留具体数值" —— 仍是替换，但不再平均化（成本：改 `_table_summary` + 重编码 22 篇 ≈ 15min）；
  2. **双向量取 max**：保留原表向量 + 额外摘要向量，score = max(两路余弦)。
     原理上不会比现状更差（原表向量仍在），是"双写"更稳的一种读法；
     代价：向量存储 2×、缓存格式与 `search_*` 都要动（改动比 1 大）。
  3. 放弃 P2（本次负结果已足够支撑"单篇设定下不适用"这个判断）。

## 5. v2 复测：保留数值的摘要（治"平均化"）—— 仍不及现状，**收口**

针对 §3 诊断的病因（摘要丢掉了具体性 → 同篇区分度下降），v2 把摘要改成
**表标题 + 列名 + 行标签全集 + 前 6 行数值样例**（`_table_summary` v2，max_len 600）：

```
表格：Table 1: Statistical summary of multilingual corpora across English, ...。
列：Language/Users/Docs/Tokens/HS Ratio。行：English、Italian、Polish、Portuguese、Spanish。
行样例：English: 64,067 83,077 20.066 .370；Italian: 3,810 5,671 19.721 .195；...
```

机制指标（`_p2_mech.py`）：

| | 原表 | v1 | **v2** |
|---|---|---|---|
| 同篇表块间平均余弦 | 0.593 | 0.616 | **0.612**（17/22 篇变高） |
| 目标块 margin 中位 | +0.033 | +0.018 | **+0.030**（变差 13 / 变好 9） |
| 逐题位次 | — | 好 4 / 差 10 | **好 4 / 差 5** |

**读法**：v2 把 v1 的损伤**收回了大半**（margin +0.018 → +0.030，接近原表 +0.033；
逐题从 4好/10差 → 4好/5差），说明"丢数值"确实是主因之一。但**仍没超过原表**：
并集增益 19 → 17，位次中位持平、位次 ≤12 少 1 题。
残留差距来自**共享成分**（caption 模板、列名在同篇表间高度重合）——只要用摘要替换原表，
就必然让同篇表块互相靠拢一点（+0.019 余弦）。

**收口决定**：
- 不再走"摘要替换原表向量"这条路（两次尝试都未超过现状）。
- 剩余可选项 **双向量取 max**（原表向量 + 摘要向量，score = max）：原理上不会更差，
  但数据显示摘要这一路**整体弱于**原表（margin 0.030 < 0.033、逐题是平局），
  只有 9/22 题靠它更好 → **预估增益 < 1 题**，而代价是向量存储 2×、缓存格式与检索路径都要动。
  **不建议做**；若将来表块向量另有需求（如跨篇检索、多文档），再回头评估。
- `PAPERPILOT_TABLE_EMBED_SUMMARY` **保持默认关**，线上行为不变；
  `Chunk.embed_text` 作为通用基建保留（任何"嵌入文本 ≠ 作答文本"的实验可复用）。
