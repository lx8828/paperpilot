# 表块表征实验：去重 / refs / 尺寸效应 — 2026-09-11

> 缘起：用户提议给表块"加表头/上下文/表格解释"。先核对实物（表头已有、caption 重复、
> refs 现成未用），再实测"加大块长到不到影响检索的级别"。
> 复算：`qa/recall/_ext_variants.py`（n=20 可定位目标表的题，表池内排名）。

## 1. 结论

| 问题 | 回答 |
|---|---|
| 表头需要补吗？ | **不用**，MinerU 的 md 已保留列名 |
| caption 重复要修吗？ | **要修，已修**（实测去重后表池 top-1 **50% → 65%**，位次净改善 4 题） |
| 加 refs（正文引用段）？ | **不加**：全量 refs 让**向量路线净 7 题变差**、块长爆炸（中位 1392、10 块 >4000 触发截断）；截断到 400 字则与去重持平（无增益） |
| 加 LLM 摘要？ | **暂不加**：**纯尺寸本身已达影响级别**（见 §3，150 字通用填充 → RRF 净 6 题变差、向量净 3 题变差、0 题变好） |

## 2. 变体实测（n=20；块长为该篇**全部**表块分布）

| 变体 | 表池 top-1 | top-3 | top-5 | 块长中位 | 块长 max | 超 4000 的块 |
|---|---|---|---|---|---|---|
| V0 现状（caption 重复） | 10/20 = 50% | 19/20 = 95% | 19/20 = 95% | 654 | 6486 | 2 |
| **V1 去重** | **13/20 = 65%** | 18/20 = 90% | 19/20 = 95% | 552 | 6415 | 2 |
| V2 去重 + refs 全量 | 11/20 = 55% | 18/20 = 90% | 19/20 = 95% | **1392** | **8300** | **10** |
| V3 去重 + refs 截断 400 | 13/20 = 65% | 18/20 = 90% | 19/20 = 95% | 863 | 6415 | 2 |
| V4 去重 + 150 字通用填充 | 10/20 = 50% | 17/20 = 85% | 19/20 = 95% | 770 | 6633 | 2 |

## 3. 敏感指标：位次位移（比 hit@k 更灵敏）

基准 = V1 去重；「净变差」= 位次变差的题数 − 变好的题数（正数 = 整体更差）。

| 变体 | RRF 位次中位 | 向量位次中位 | BM25 位次中位 | RRF 净变差 | 向量净变差 | BM25 净变差 |
|---|---|---|---|---|---|---|
| V0 现状（含重复） | 0.5 | 0.0 | 1.0 | +4 | +2 | +1 |
| **V1 去重** | **0.0** | **0.0** | 1.0 | 基准 | 基准 | 基准 |
| V2 +refs 全量 | 0.0 | 1.0 | 1.0 | +4 | **+7** | −2 |
| V3 +refs 截断 400 | 0.0 | 0.0 | 1.0 | +2 | 0 | −1 |
| **V4 +150 字纯填充** | **0.5** | 0.0 | 0.5 | **+6** | **+3** | −1 |

**机制**：
1. 表块的向量是"整块文本的平均语义"。加**通用文字**（V4）会稀释它 → 向量路线净 3 题变差；
   BM25 反而略好（多命中几个词，长度归一化的损失更小）→ 合到 RRF 上净 6 题变差。
2. 加**相关但冗长的正文**（V2 refs）更糟：向量净 **7** 题变差——正文散文的表达方式与
   "表里某个数是多少"这类提问不匹配，反而把表块向量拉离了目标语义；同时块长 5 倍化。
3. 因此**"加长"本身就有代价**，必须先证明"信息增益 > 尺寸代价"才能加。

## 4. 已落地的修复

`document_cache._external_table_chunks`：删除多余的 `cap` 拼接。
原因：`element_text` 对 table 类型**已返回 `cap + body + footnote`**，旧代码又拼一次
`table_caption` → caption 在块内出现 2 次（实测 `xtbl-25`: 919 → 604 字）。
它与 `PAPERPILOT_QASPER_TABLES=1`（默认关）同域，**不影响线上默认行为**。

⚠️ 副作用（预期内）：`ChunkIndex` 的缓存指纹**含文本 md5**，故表块文本变化会
**使表通道下的 cvec 缓存整体失效并重建**（176 篇约 3.5h）。这是正确的（旧向量本就该作废）。

## 5. 若将来要加 LLM 摘要，怎么做才算验证过

1. 只对**表池里已排到 top-3 却仍失败的题**生成摘要（小样本、便宜）；
2. 用本文件的 V3 槽位替换成**真摘要**重跑 `_ext_variants.py`，要求
   **向量净变差 ≤ 0 且 RRF 净变差 < 0**（即信息增益压过尺寸代价）；
3. 通过后再做 A 桶端到端（注意：端到端噪声 ±2 题，见 `WEIGHT_SWEEP_20260911.md`）。

## 6. 追加修复（2026-09-12）：caption 清噪声 + 给**无 caption 的表块补身份**

### 6.1 上游缺陷（MinerU，`qa/recall/MINERU_COVERAGE_20260912.md` §5）

MinerU 的 `table_caption` 字段会混进无关文本，**而我们的代码是原样拼进块**：

| 论文 | `table_caption` 原文 | 混进了什么 |
|---|---|---|
| `1804.08139` | `['Figure 6: Attention Distributions...', 'Table 4: Average precision...']` | 上方**图的标题** |
| `2002.10361` | `['Age Race Gender', 'Table 3: Annotator agreement...']` | **表头行文字** |

另外 MinerU 会**把一张表切成多个 `type=table` 元素**，只有其中一块带 caption
（`2002.10361`: xtbl-58/59/60 表头相同、只有 xtbl-60 有 caption）。

### 6.2 改了什么（`document_cache.py`，默认生效、与 `PAPERPILOT_QASPER_TABLES` 同域）

1. `_clean_table_captions`：`table_caption` 片段**从首个 `Table <编号>` 处截断**，
   不含 `Table` 的片段整段丢弃 → 同时清掉"图标题"与"表头文字"两类噪声。
2. `_table_header_cells` + 两遍扫：
   - **借**：同篇内表头单元格集合相同的兄弟块已有 caption → 抄过来；
   - **补**：借不到就拼一行 `表格（列：A、B、C）`（不加长、不加新信息，只给 BM25/向量一个锚点）。
3. 只对**无 caption 的块**补 —— 不给已有 caption 的好块加料（§5 的 refs 全量实验已证有害）。

### 6.3 结构自检（非基准测试）

```
2002.10361 xtbl-33: 首行 'Age Race Gender Table 3: ...'  →  'Table 3: Annotator agreement ...'   ✅ 噪声清除
2002.10361 xtbl-58: 首行 '| Language | Method | Acc ...' →  'Table 5: Overall performance evaluation of baseline classifiers...'  ✅ 借到
1804.08139 xtbl-92: 无 caption                        →  'Table 4: Average precision of multi-task models with auxiliary tasks.' ✅ 借到
1804.08139 xtbl-102: 首行 'Figure 6: Attention ...'    →  'Table 4: Average precision ...'          ✅ 图标题清除
公式块（xtbl-70 '公式: ...'）                        → 不变                                    ✅
```

⚠️ 借来的 caption **编号可能仍是邻居的号**（xtbl-92 借到的是 Table 4，实际可能是 Table 3）。
这不影响检索（编号不参与打分），但对**按编号定位目标表的评测口径**是又一条不能用编号的证据。

### 6.4 规模与预期

无 caption 表块 **32/192 ≈ 16.7%**（`_nocap_probe.py`）：其中 **3 块**可借到真 caption、
**27 块**用列名拼身份、**2 块**两者都无。受影响面约 1/6，且多是"同一张表的碎块" →
**定位为顺手修掉的确定性缺陷，不指望端到端显著**（未跑基准，按约定先不测）。

⚠️ 副作用同 §4：表块文本变化 → 表通道 cvec 缓存整体失效重建（176 篇约 3.5h）。

### 6.5 自测抓到的 bug（已修）：清噪正则漏了**罗马数字表号**

写边界自测（`qa/recall/_selftest_tables_20260912.py`）时发现：`_TBL_CAP_RE` 首版写成
`Table\s+[IVXLC]*\d+` —— 只认"罗马前缀 + **数字**"，于是 `TABLE IV COMPARISON` **不匹配**
→ **整段真 caption 被当噪声删掉**，该块退化成"无 caption"（去借兄弟块或只拼列名）。

**修复**：`Table\s+(?:[IVXLC]+|\d+(?:\.\d+)*[A-Za-z]?)`（罗马号 / 带后缀阿拉伯号 `Table 5a` / 小数号 `Table 3.1`）。

**影响面**：A 桶 33 篇里 **3 篇**含罗马数字表号（`1901.00439` 2 张、`1901.00570` 4 张、
`1909.13362` 3 张，共 9 张）。这些表在修复前丢了 caption → **修复只会让它们重新拿到身份**，
所以已报出的检索层/端到端数字（并集 15→19/36 等）在这一点上是**偏保守**的，没有被高估。
生产链路已复核：`1909.13362` 的 `xtbl-75` / `xtbl-76` 现在首行分别是 `TABLE I` / `TABLE II`。

**教训**：表号有两套书写体系（阿拉伯 / 罗马）＋带后缀变体，任何"认表号"的正则都要三样都覆盖，
且必须配一条**罗马数字**的回归用例（这次正是靠它抓到的）。
