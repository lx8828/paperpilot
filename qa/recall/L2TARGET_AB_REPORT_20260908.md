# L2 目标题群 A/B（2026-09-08）

> 目的：修正在错误人群上测 L2 的方法论（此前用 recall hard/normal——hard 本就该走全局 L3，
> 拿它测"L2 该不该留"是测错了对象）。L2 的服务对象 = **judge_l1 判不够但给了 target_sections**
> （有局部方向的中等问题），L2 在局部扩窗解决以省下 L3 全文的 token。
> 本实验只测这批题：A=现状（judge_l1 不够 → expand_l2 扩窗） vs B=砍 L2（同判定 → 直接 search_l3），
> 同 judge_l1 判定同题端到端 + 同一外部裁判 glm-4-flash。
>
> 产物：`ab_l2target_result.json`（逐题，含 route/judge_l1 debug/usage）、runner `_ab_l2target.py`、
> 报告脚本 `_l2target_report.py` / `_l2target_miss.py`。样本 80（hard源35 / normal源45），**0 err**。

## 三层解读

**① L2 的减负卖点成立（但只在 normal，且准度不占优）**
- 双过 34 题（A/B 都答对）里 **21 题 A 在 L2 层就答对**，整组 token 比 A/B=0.71 → **同样答对时 L2 省 29%**；
- normal 全程 A 省 38% prompt（10.5K vs 17.0K）——因为 L3 是"多查询混合全文检索"，每次塞 15-30K 上下文；
- 但准度上 B(直L3) 仍更高（目标群 44>40，normal 41>39）——省 token 换来了小幅准度损失，不是白赚。

**② judge_l2 判够太松是漏题主因（9/10）**
- 净亏 10 题里 **9 题 A 终点 = L2**（judge_l2 判 enough → L2 answer），分数 2-3；B 直 L3 同题 4-5。
- 即这些题 judge_l2"判够"放行作答，但 L2 窗口材料不足以答出好答案 → 正是用户策略③所指
  （judge_L2"够不够精确作答"标准太松）。若 judge_l2 更严（判不够 → 降级 L3 兜底），
  这 9 题可被 L3 救回（B 已证明 L3 能答 4-5）。
- 仅 1 题（05671d068679）A 掉 L3 仍错 → 属圆心/检索问题，非判够误放。

**③ hard 不该进 L2（继续印证）**
- hard 子集：A 9 vs B 12，且 prompt 几乎没省（12.4K vs 12.9K，仅省 4%）→ L2 在 hard 上
  既不省钱也不更准，hard 应在 judge_l1 就直接 L3，不进 L2。

**净赢 6 题（L2 独有价值）**：5 题 A=4-5 vs B=3，A 靠 L2 扩窗拿到更全材料答得更完整；
1 题是 unknown 差异。方向真实但量小。

## 结论：不是砍 L2，是"限定服务对象 + 收紧判够"

修 L2 的收益上限 = 净亏 10 题（主要靠策略③收紧 judge_l2 → 判不够即降 L3），
同时保住双过 34 题的省 token（29%）不受伤。而 hard 直通 L3 是独立且更便宜的路由改动。

对比上次在错误人群上的结论：上次"hard 上 L2 净负 → 倾向砍"是把"hard 不该走 L2"当成了
"L2 无用"。本实验在 L2 目标题群上看到：**L2 存在价值（省 token 面真实），问题在判够过松与
hard 误入**——修法方向是策略③ + "hard 直 L3"门，不是砍掉 L2。
