# 失败题归因：是判分/题集的问题，还是我们系统真做得不好？（2026-09-11）

> 样本：**QASPER 500**（无偏子集，`qasper_run_20260911_072510.json`）主口径 +
> **QASPER 233**（同源集，`qasper_run_20260911_052532.json`）交叉验证
> 方法：`qa/recall/_fail_attrib.py`（零 LLM 启发式首过）——按"gold 内容是否**可达**→ 是否**送达**→ 是否**被采用**"分桶

## 分桶结果

| 桶 | 含义 | 500 题 | 233 题 | 归属 |
|---|---|---|---|---|
| **A 输入通道缺口** | gold 的答案内容在论文**正文段落**里根本不存在 | **36** | **13** | **基准边界**（非系统缺陷） |
| **B 送达/检索失败** | 正文里有，但没进 cites（没送到作答层） | **14** | **9** | 我们的 |
| **B0 闸门兜底** | 答案被输出闸门拦成"未能通过内部事实校验" | **4** | 0 | 我们的（系统自伤） |
| **C answer 层漏用** | cites 里已有 gold 内容，答案没采用 | **7** | **3** | 我们的 |
| **D 疑似判分过严** | 答案里已含 gold 关键内容仍判 fail | **2** | **2** | 判分 |
| 合计 | | **63**（/451 有答案题） | **27**（/212） | |

## 结论一：**判分基本不是问题**（2/63 = 3%）

有答案题的 63 道失败里，只有 2 道是"答案已含 gold 内容却仍被判 fail"。
→ **裁判（glm-4-flash）不是主要噪声源**，不必再纠结换裁判。

> 该桶是**启发式**判定（gold 关键数字出现在答案里）。要严格可对 63 题换第二裁判复核（~0.3 元），
> 但量级上不会改变结论。

## 结论二：**"QA 集问题"是大头，但性质不是"标注错"，是"数据集没给文本"**（36/63 = 57%）

> ⚠️ **口径更正（2026-09-11 晚，见 `STILL_FAIL_DIAG_20260911.md`）**：A 桶 36 题**口径过宽**——
> 按 QASPER 标注的 evidence 类型重算：**`TABLE`/其他 float 23 题 + `FIGURE` 1 题 = 真表格类 24 题**，
> 另 **12 题是非 float**（gold 措辞与正文差异大，无数字，被启发式误判为"不可达"），
> 那 12 题的失败原因在 **answer 层/裁判口径**，与输入通道无关。
> → "通道缺口"应记为 **≈5.3pt（24/451）而非 8.0pt**。

决定性证据（本机数据集实查）：

```
paper 2002.11402 的 figures_and_tables：
  [0] keys=['file','caption']  file = 2-Table1-1.png   caption = ['T','a']（字符 span）
  [1] keys=['file','caption']  file = 3-Table2-1.png   caption = ['T','a']
```

**QASPER 的表格只提供一张 PNG + caption 的字符 span，没有任何表格数值的文本形式。**
而这类题的 gold 恰恰是表里的数值（例：`2002.11402` 的 gold = `42.91, 25.03, 69.8, 49.88, 43.36, 62.43`，
evidence 标注为 `FLOAT SELECTED: Table 2`）。

→ 对**任何只消费 QASPER 文本**的系统，这 36 题**结构上不可能答对**；系统的表现（"证据只给出定性描述"）
是**正确行为**，不是答错。这与 `CAMPAIGN_20260906-07.md` §6 的归类一致（表格/图数据层 = 输入通道边界）。

## 结论三：**我们真正的问题只有 ~25 题（40%），约 5.5pt**

| 可改项 | n | 占全部有答案题 | 说明 |
|---|---|---|---|
| 闸门兜底（系统自伤） | 4 | 0.9pt | 与已修复的 10 道同源，属**残余误杀**，可继续修 |
| 送达/检索失败 | 14 | 3.1pt | gold 在正文里却没进 cites → 检索/选取要改 |
| answer 层漏用 | 7 | 1.6pt | 证据已在 cites 里，答案没采用 → answer 层要改 |
| **合计** | **25** | **5.5pt** | —— |

**换算成水位**：有答案题 pass 386/451 = **86.0%**，其中
- **8.0pt 是基准输入通道卡住的**（36/451）
- **0.4pt 是判分**（2/451）
- **5.5pt 才是我们系统的**（25/451）

## 由此得到的两个可行动作

1. **真正的 MinerU 用武之地在这里**：这 36 题的原文都在 arXiv（paper id 即 arXiv id），
   **可以拉原始 PDF → 解析表格 → 补进输入通道**。理论上可回收最多 **+8pt**。
   ⚠️ 注意口径：这是"给系统**额外**输入"的条件，必须**单列报告**，不能与"纯 QASPER 文本"口径混报
   （也正好回答了"MinerU 收益量不出来"——本地区库那个 A/B 是天花板，**这里才是它的战场**）。
2. **我们的 25 题分两条修**：闸门残余误杀（4，最低成本）、检索送达（14，最大块）。

> 复算命令：`uv run python qa/recall/_fail_attrib.py <run.json> --show 6`

## 附：剔除「不可归因于系统」后的统计口径

剔除项 = **A 输入通道缺口**（QASPER 表格只有 PNG、无数值文本 → 任何只用 QASPER 文本的系统都无解）
+ **D 疑似判分过严**。

| 口径 | QASPER 500（无偏） | QASPER 233（同源） |
|---|---|---|
| 原始 主通过 | 424/503 = **84.3%** | 202/233 = **86.7%** |
| 原始 合格（含 `excerpt_ok`） | 431/503 = 85.7% | 205/233 = 88.0% |
| 剔除题数 | **38**（通道缺口 36 + 判分 2） | **15**（13 + 2） |
| **剔除后 主通过** | **424/465 = 91.2%** | **202/218 = 92.7%** |
| **剔除后 合格** | **431/465 = 92.7%** | **205/218 = 94.0%** |
| **剔除后 有答案题** | **388/413 = 93.9%** | **185/197 = 93.9%** |
| 剔除后 无答案题（合格口径） | 43/52 = 82.7% | 20/21 = 95.2% |

**两批独立样本的"有答案题"剔除后都是 93.9%（388/413 与 185/197）** ——
两个随机样本收敛到同一点，说明该口径**稳定**，不是挑数挑出来的。

⚠️ **口径纪律（重要）**：此表**必须与原始口径并列出现，不得单独对外宣称**。
它是"把对任何只用 QASPER 文本的系统都无解的题（表格=PNG）与判分存疑题剔掉"后的**条件值**，
属**能力上限口径**，不等于"我们答对了 93.9% 的 QASPER"。

## 结论：调优到此为止（用户决定，2026-09-11）

剔除不可归因项后，**我们系统真正可改的只有 25 题 / 5.5pt**：
闸门残余误杀 4（0.9pt）、检索送达 14（3.1pt）、answer 层 7（1.6pt）。
且三者互相牵连（改送达可能动闸门、改 answer 可能动拒答），**收益小而返工风险大** → **不再反复调优**。
无答案题那 82.7% 属**格式税**（"首句是否明确拒答"），已单列口径，不计 fail。

**下一步的正确方向不是继续调参**：
1. 要提水位，走**输入通道扩容**（拉 arXiv 原始 PDF 解析表格 → 理论最多 +8pt，须单列口径）；
2. 或走**多篇/MCP 工具化**（新场景，不是单篇调优）。
