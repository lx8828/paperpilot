## 4. 可达性诊断（补做，0 元纯解析）——为什么三臂齐平

三臂 pass 全 100% 属**天花板**，A/B 分不出 MinerU 的收益。追问更本质的一层：
**这些"金标准在表格里"的数字，本来就在各臂的检索文本里吗？**

命令：`$env:PP_ARM=<arm>; uv run python qa/recall/_reach_diag.py`（三臂须分进程，`document_cache` 有 lru_cache）

| 臂 | 解析源 | gold 数字命中 | 全数字可达的题 |
|---|---|---|---|
| A0 plain | pymupdf | **90/90** | 11/11 |
| A1 inject | pymupdf（+注入） | **90/90** | 11/11 |
| A2 mineru | mineru | **90/90** | 11/11 |

**结论**：这 10 篇上 **pymupdf 的文本层已含全部 90 个金标准数字**（11/11 题全可达）
→ MinerU 的表格注入**不提供"新增可答信息"**，注入的 ~21k 字符（`2609.01316v1` 实测 +24%）是**表格文本的冗余副本**
→ 这也**解释了三臂为何齐平**：信息本来就在文本里。

**边界（必须说清）**：
1. 本诊断只证"数字**在不在**文本里"，不证"**好不好检索**"——pymupdf 会把表撕碎、丢行列关系，
   结构化仍可能改善**排序**；只是本套题已顶格，看不到这部分收益。
2. 样本仅 10 篇、且是**挑出来的正常论文**（无扫描件、无复杂跨页表）→ **不能外推为"MinerU 无用"**。
   扫描件/双栏/复杂表在 pymupdf 下文本层为空或错乱，那类 PDF 上 MinerU 仍是唯一解。
3. 要真正量化 MinerU 收益，需**只在表里、且 pymupdf 抽不出来**的题（本集 0 题达标）；
   或改用**检索层指标**（表值能否被 top-k 召回）替代端到端 pass。
