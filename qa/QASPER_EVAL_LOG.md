## V1 基线（2026-09-05，评测 bug 修复后）

### 1. 测了什么

| 项 | 值 |
|---|---|
| 数据集 | QASPER train（888 篇中的采样 80 篇，每篇跑其全部问题） |
| 样本 | 80 篇论文 / **233 题**（`qa/qasper_run_20260905_224146.json`） |
| 样本来源 | 复用 `qasper_run_20260905_200513.json` 的论文列表（同 80 篇可比） |
| 题目形态 | gold 自带：描述性 18 / 枚举·多维 18 / 数字 10 / yes-no 5 / unanswerable 1（fail 口径内） |
| 全量分型 | 枚举/列表 90+，描述性 ~90，含数字 ~40，yes/no ~45，unanswerable ~15（约） |

### 2. 怎么测的

```
80 篇 QASPER 论文（qasper_<id>.qpdf，文本源，无 PDF 版式）
   → process_pdf 产物 report（有缓存则复用，见 out_views/qasper_*.report.*）
   → 逐题 graph.ask（L0→L1→L2→L3→unknown 漏斗，QA_FUNNEL_DESIGN.md v1.1）
   → 系统回答 + cites（引用锚定检索结果）
   → GLM-5.3 裁判（PAPERPILOT_JUDGE_*，与主链路异源）对比 gold+evidence vs 答案+cites
   → score 1~5，≥4 = pass
```

判定口径：
- `pass`：裁判 ≥4
- `fail`：裁判 <4（且非 unknown）
- `unknown_ok`：系统走 answer_unknown（诚实说不知道，判分 1~3 不罚，作为"没硬编"的观察桶）
- `honest_refuse`：**gold 无答案**（unanswerable）且系统答 unknown = 好行为
- 系统对无答案题强答 → 按裁判分进 pass/fail

**2026-09-05 已修的评测 bug**（V1 起生效，见下）：
1. `answer.py` chunk 类型 cites 的 evidence 从 `[:120]` 放开为完整 chunk 文本
2. `run_qasper_eval._judge` cites 展示不再截断 200 字符
3. `llm.judge_json` 宽松 JSON 解析（GLM reason 含裸引号/换行不再解析失败）
4. run 记录保留完整 answer + cites（供离线重判）

## 优化实验记录（V2 起，持续追加）

### 实验 E1：浅层 fail 强制深潜到 L3，测回报率（2026-09-06 已跑）

**动机**：V1 fail 中 40 条停在 L1/L2（judge 判"够"就收口）。若放宽下钻条件，
这 40 条会进入 L3 全局检索。改漏斗前先量化"深潜回报率"：
若强制 L3 也救不回几条 → 说明问题不在深度而在 answer/judge 行为，P0-2' 应放弃；
若救回很多 → 定向深钻值得做。

**方法**：对这 40 条浅层 fail，跳过 L0/L1/L2 判定，直接 `search_l3 → judge_l3 → answer/unknown`
（复用 V1 的 L3 检索 + GLM 裁判），对比 fail→pass 转化数。
记录：`qa/qasper_deep_20260906_010435.json/.md`

**结果**：

| 深潜后 | 数量 | 说明 |
|---|---|---|
| **pass（救回）** | **15 / 40** | 原来能答但 L1/L2 证据不足/引用截断 → L3 全文捞到细节后答对 |
| fail（没救回） | 13 | 其中含 1 条裁判超时(0分)，其余多为"表格数值/枚举仍不全" |
| unknown_ok | 12 | 深潜后仍无把握 → 诚实拒答（比原 fail 的硬编好，但仍是漏检） |

**关键洞察（deep pass 的 15 条深潜 score 中位数 = 5）**：
- 救回的题大多是 **V1 时"引用截断"或"L1/L2 窗口只捞到定性句"造成的**——
  如 `1911.08673`(3→5)、`1704.02385`(3→5)、`1708.08615`(2→5)；
  修复 cites 截断后，L3 全文让裁判看到了完整证据。
- **没救回的 13 条里，多数问题在 answer 行为而非检索深度**：
  `1910.05456` 系统与自身引用原文矛盾、`2001.07209` 枚举仍缺 MFD、
  `1909.01013` 表格数值 L3 全文也没有 → **深潜救不了表格/枚举不全/理解偏差**。

**结论 → P0-2' 定向下钻成立但收益有限**：
- 若全量把 40 条浅层 fail 强制下钻 → L3 负载 38%→55%，只多救回 **15 条**（其中还含
  已被 cites 截断修复部分抵消的题）。
- 因此正确策略是**先做 P0-1（answer prompt 校准）+ 已生效的 cites 全文**，
  P0-2' 只对 judge 报"缺数字/枚举"的定向下钻，避免全量摊薄漏斗。

### 实验 V2-A：judge 题型完整性自检（2026-09-06 已跑）

**动机**：V1 有 41 条浅层 fail（停在 L1/L2），根因是 **judge 把"相关"当"完整"**——
列举题拿到 3 项就判够（实际 7 项）、数字题拿到定性就判够（没数值）、对比题只见单边就判够。

**改动**（方案 A，纯 prompt，零结构改动）：`judge.py` 给 L1/L2 模板注入 `_COMPLETENESS` 段，
要求 judge 判 enough 前先按题型自查：
- 列举类 → 必须列出**全部**成员，见 "such as/e.g./等" 即判不够
- 数字类 → 必须有**具体数值**，定性比较不算
- 对比类 → 必须覆盖**所有被比对象+维度**
- 方法类 → 必须覆盖**完整步骤**

**方法**：对 V1 的 40 条浅层 fail 走**完整漏斗**重跑（不跳过 L1/L2），GLM 裁判打分。
记录：`qa/qasper_judgeA_20260906_021512.json`

**结果**：

| 结果 | 数量 | 说明 |
|---|---|---|
| **翻 pass** | **14 / 40（35%）** | 与 E1 强制 L3 的 15/40 几乎持平，但走完整漏斗、没跳层 |
| 仍 fail | 21 | 表格数值/枚举不全、理解偏差答错对象、yes/no 不肯下结论 |
| unknown_ok | 5 | 下钻 L3 仍无把握 |

**关键观察**：
- 翻盘的 14 条里 9 条在 **L2 半径 0（单块）** 就答对——完整性自检逼 judge "多判一轮/换对窗口"，而非需要疯狂扩半径
- **L2 扩窗预算（半径 3 / 6 chunk）够用**：翻盘组平均用 1.8 chunk，预算耗尽才放弃的仅 3/12。
  只有 2 条走到半径 2~3 + L3（`1911.08673`、`2001.05493`），现有 MAX_RADIUS=3 已覆盖。
  → **暂不需要加大扩窗参数**，加了反而可能让 L2 空转。
- 剩余 21 条 fail 归因：
  - **answer 行为问题**（答错对象/不肯下结论）：`1809.01060` 答错实验、`1708.05592` 训练vs评测数据、
    `1901.02534` 答错基线、`1910.05456`/`2004.04315` yes/no 不下结论 → **P0-1 的主场**
  - 表格/深层枚举：`1909.01013` 数值、`1909.09018` Hierarchical Model → 数据源限制

### 实验 V2-B：answer prompt 校准（P0-1，2026-09-06 已跑）

**动机**：V2-A 后仍 fail 的 21 条里，一部分是 answer 行为问题：
yes/no 不下结论 / 答错对象 / 滥用"信息不足"。

**改动**（方案 P0-1，纯 prompt）：`answer.py` 的 SYSTEM prompt 加 5 条回答准则：
1. yes/no 题必须给明确"是/否"，不得用"无法确认"回避；
2. 回答紧扣问题对象，不张冠李戴（训练数据 vs 评测数据、任务 A vs 任务 B）；
3. 不滥用"信息不足/论文未提及"——证据已有答案就必须作答；
4. 问"哪些/什么/多少"要列全成员/给数值；
5. 禁止编造。

**方法**：从 V2-A 仍 fail 的 21 条定向重跑（新 answer prompt，judge 保持 V2-A 版本）。
记录：`qa/qasper_judgeA_20260906_023404.json`

**结果**：**翻 pass 4 / 21（19%）**，仍 fail 17。

**结论**：
- P0-1 有效但**边际收益小**（4 条 vs V2-A 的 14 条）。prompt 让系统"更敢答、不滥用信息不足"，
  但**救不了"该找的证据没找齐"**。
- 剩余 17 条 fail 分两类，都不是 prompt 能救的：
  ① 检索/答案散布型（~10 条）：关键细节在别的段落/小节，L2/L3 没捞齐
     （`1704.02385` 标注方法缺 AMT 细节、`1708.05592` IHM 段没进窗口…）
  ② 结论方向与 gold 冲突（~5 条）：下错结论而非不下结论（`2004.04315` 答"否"gold"是"、
     `1910.05456` 自相矛盾、`1909.01013` 缺表格数值…）
- **prompt 校准（V2-A + P0-1）的边界已探明**：合计翻盘 ~18 条后，剩下的是检索覆盖问题 → 指向 P1。

### 边界确认：一类"问题歧义"型 fail 判定为不可治（2026-09-06）

对 V2-A + P0-1 后仍 fail 的 17 条逐一深度打开（dump L1 claims / L2 窗口 / L3 chunks），
发现其中 **3 条（+同类若干）是"问题歧义"而非系统缺陷**：

| 题 | 论文同时存在 | 系统答 | gold 选 |
|---|---|---|---|
| `1708.05592` Which dataset do they use? | 训练 AMI+Fisher / 评测 AMI IHM | 训练数据 | 评测数据 IHM |
| `1901.02534` What baseline do they compare? | 检索基线 / entailment 分类基线 | 检索基线 | 分类基线 |
| `1809.01060` results of the first experiment? | 人类评分实验 / 模型实验(0.72 F1) | 人类实验 | 模型实验 |

**为什么判定不可治**：
- 问题文本本身没指明子概念（"dataset/use/baseline/first experiment" 都是泛称），标注者的
  gold 选了论文里**不显眼**的那个；embedding 排"显眼段"第一是**正确的检索行为**。
- E1 已证明：强制 L3-only 独立全文检索同样答不出（`1708.05592` E1=unknown）——换 embedding
  模型/换检索深度都改变不了"问题歧义"。
- 结论：**这类是 QASPER 基准的固有噪音（标注者心里 target 不在问题文本里），不是检索式 QA
  系统该纠结的**。真实用户问"用了哪些数据集"时，系统列全（训练+评测）反而是好答案。

### 实验 V2-C：judge_l3 放宽（2026-09-06 已跑）——最大单点收益

**动机**：诊断发现 38 条题"L3 检索到答案 chunk 在 top8（甚至 top1），仍 fail/unknown"。
深挖 6 条后锁定根因：**judge_l3 要求"段落直接包含能作答的原句"**，把"段落没直接写出答案句"
（需跨段拼凑/简单推断，如 4262/150≈27.4、Zipf/Heaps 定义分散 3 段、baseline 分散 3 chunk）
误判为"论文没有" → enough=False → answer_unknown → 白白丢掉已检索到的答案。

**改动**（纯 prompt）：`judge.py` 的 `_SYS_L3`/`_L3_TPL` 从"严格找原句"改为：
- 检索到**实质信息**（数字/定义/列举/对比依据，允许跨段拼凑/推断）→ enough=true
- 只有检索结果**与问题完全无关**时才 enough=false
- 明示"你是兜底层，判 false=放弃作答，别因没直接答案句而误判不够"
- LLMError 降级仍保持 enough=False（防编造）

**方法**：对 38 条"L3 答案在 top8 仍 fail/unknown"定向重跑完整漏斗。
记录：`qa/qasper_judgeL3_20260906_034500.json`

**结果**：

| 结果 | 数量 |
|---|---|
| **翻 pass** | **15 / 38（39%）**（unknown→pass 12，fail→pass 3） |
| 仍 fail | 17 |
| 仍 unknown | 6 |
| 副作用（unanswerable 误答） | **0** |

**结论**：
- judge_l3 之前是**"过度严格"**——与 V2-A 给 L1/L2 加严是同一思路错用在兜底层。
  V2-A 让 L1/L2 严格是对的（还有下层可下钻）；judge_l3 严格 = 直接拒答 = 永久丢失。
- 仍 fail 的 17 条已**不再拒答**（judge 放行），暴露下一层问题：answer 拿到含答案的 chunk
  但**提取不全**（枚举漏项、数字在 Table 提不出、推导不出 2000-300=1700）→ answer_l3 能力层。
- 仍需打磨的是 answer 从多 chunk 拼凑/提取的能力。

### 无答案题口径修正：新增 `excerpt_ok`（2026-09-11）

**问题**：V3 的 `unknown_ok = 0`（`nol3j` 变体下 `answer_unknown` 图内无入口，`qa_graph_v3.py:83`），
无答案题的答案形态由"首句明确拒答"变为"先给相关原文片段、末尾说明论文未直接给出"。
裁判按**回答完整性**打分 → 给 3（不到 pass 线），使该桶从 95.2% 掉到 66.7%。

**判定**：后者对用户是**有效交付**（可自行判断），产品口径为**合格**，不应计 fail。

**改动**：`cli/run_qasper_eval.py` 新增 `excerpt_ok` 状态 —— **仅对 gold 空的无答案题**：
未给结论、但 ①`_absence_tone(answer)`（明确说明论文未提供）②有 cites（给了材料）
→ `excerpt_ok`，不计 fail。**有答案题出现同款缺失口吻仍判 fail**（那是误断言缺失）。

**结果**：该桶 **66.7% → 85.7%**；主通过率不变（`excerpt_ok` ≠ pass）。V2 记录同口径重判
**0 变化** → 该改动只校正新行为，**不追溯抬高历史成绩**。

**工具**：`qa/recall/_rescore_unans.py`（零 LLM，可对任意历史 run 复算分桶）。

**剩余 3 题真 fail**：`2003.09971` ×2（对象错位：把"实验设置 / 对比基线"当成"环境 / 性能数值"答）、
`2001.07209`（闸门兜底话术且 cites=0，用户什么都拿不到）。

**职责边界**：本系统**不做**"用大模型自身知识补答"——留待将来 MCP 化后由**外层 agent** 承担
（决策与理由见 `DEVELOPMENT_LOG.md` 阶段 S 认知 7）。
