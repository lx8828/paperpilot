## 0. 一句话定位

**问题**：想用"大范围、权威、异源"的测试回答两件事——① 我们自评测试集不够权威，换外部基准测出来真实水位是多少；② 到了 75~90 分这个阶段，还值不值得继续修、修什么。

**答案（一句话）**：QASPER 1000 全新题实测 **75.0%**（与旧 233 题 75.5% 双样本一致，这是真实水位）；残差是两座山——约一半"检索/材料送达不到位"、约四成"材料到了但模型没答好（模型能力，pro 可救 7/12）"；收口决策=**不修 prompt、②类靠模型选型、①类检索/数据层是唯一剩余工程方向（MinerU 优先）**。

## 1. 阶段一：新批次外推（10 篇 2026-09 arXiv × 100 题）

- 目标：用跨出原 NLP 主分布的最新 LLM-Agents/对齐/系统论文做首次外推 QA（每篇新写 10 题 dev/user）。
- **运行中修掉一个被缓存掩盖的回归**：`figures.py` 的 `_CAP_HEAD_RE` 捕获组在 `0e6848e`（类型收敛）被误改成非捕获组 `(?:...)`，新论文无缓存首跑 `extract_figures` 必崩（`IndexError: no such group`）。已修复；bench 的 FIG 增加"无缓存本地重算"用例防再犯。
- **首跑结果**：100 题 0 崩溃，✅87 / ⚠️13 / ❌0（语义口径 ≈90/100）。13 条 ⚠️ 分三类：A 标注措辞过严 3、B 缺细节数值 4、C 真系统缺口 6（其中 4 条是"论文没写"式误断言，回原文逐字核验 3 条坐实数值/原因实际存在）。
- 信号：L3 深潜作答 16/16 全对 → **质量缺口不在检索深度，在 answer 的缺失断言与浅层收口**。

## 2. 阶段二：缺失断言复核闸门（已落地）

- 实现（`agents/nodes/answer.py`，不改图结构）：浅层 L0/L1/L2 答案若带"论文没写/未给出/找不到"口吻，自动做一次 L3 独立全文复核（`ChunkIndex.search_hybrid` 向量+BM25）：可作答则 L3 重答，确无才保留原答案。
- 正则覆盖含副词变体（"未在正文中给出/并未明确说明"等）。
- 效果：定向探针 4/4 救回（02786-06→ASR 2.37→0.79、02056-U2→HGT 29.99%、03718-U3→80.9/92.7/96.4、04170-U2→失败根因）；100 题重跑 ✅87→**89**，0 回归；真实缺口收敛到 2 条（02056-04 浅层漏规则、03335-07 yes/no 缺席拒答）。

## 3. 阶段三：整夜 QASPER 1000 题扩量评测（核心）

### 3.1 数据与采样
- QASPER 本地：train 888 篇 / 2,593 题（dev 281 篇 / 1,005 题未接入管线，`qasper_source` 只挂 train）。
- 采样：train 全库随机（seed 20260907 可复现），**排除历史已评 242 题** → 全新、未参与任何调参。
- 规模：目标 1000；实测跑满 **1000/1000**。

### 3.2 工程实现（可复用资产）
- 2 worker 并行（各 ~500 题，论文分片交错），supervisor 崩溃自动续跑；**逐题落盘 JSONL**（`qa/qasper_overnight_w{0,1}.jsonl`），断点续跑不丢已评。
- 本地看门狗每 10 分钟探活 supervisor；每小时自动化巡检（含"停滞检测"：连续两轮无增长即强制重启——针对"不崩但卡住"）。
- 复用 `cli/run_qasper_eval.py` 的问答+裁判逻辑（异源裁判 1~5 分，≥4 pass）。

### 3.3 事故与根因（重要教训）
- 凌晨 00:46 起裁判全挂（score=0），worker 双双停滞 2 小时。根因：`.env` 里 `PAPERPILOT_JUDGE_*`（glm-5.3 / 低余额 key）**已无余额（HTTP 429）**；历史成功的 QASPER 跑批都是在启动脚本里把裁判临时镜像到主链路 key，本次 supervisor 没做。
- 修复：worker 启动时 `_sync_judge_from_main()`（裁判=主链路同账号 deepseek-chat）；并把 worker/supervisor 改为各自直写日志（原管道转发导致 2 小时无日志可查）。
- 教训：① 评测基建要自带"自愈+可观测"，不能依赖单一长进程；② 裁判与主链路要分离配置，余额/可用性要启动自检。

### 3.4 结果（2026-09-07 06:51 完成，约 4.2h，0 error）
| 指标 | 数值 |
|---|---|
| 通过（≥4） | **750 / 1000 = 75.0%** |
| fail / unknown_ok / error | 190 / 60 / **0** |
| 均分 | 3.94（5:535、4:215、3:27、2:106、1:117） |
| 有答案题（896） | pass 660（73.7%）/ fail 176 / 拒答 60 |
| 无答案题（104） | 诚实拒答且裁判认可 90 / 未认可 14 |

**关键结论**：旧 233（含调参）=75.5% vs 新 1000（全新）=75.0%，**双样本一致 → ~75% 是当前 flash 管线的真实外部水位**，非小样本虚高。

## 5. 收口前做的三个验证实验

1. **换模型 A/B（pro）**：链路模型 `deepseek-chat(v4-flash)` → `deepseek-v4-pro`，同题、裁判不变。16 题（12 非pass+4 对照）：**7/12 翻绿，4/4 对照零回归**，多为 L3/枚举/拒答类大跳（1→5、2→5）。→ **② 类确认为模型能力问题，不是 prompt 可修**。
2. **yes/no 细拆**（157 题 yes/no，45 非pass 逐条分类）：A 真没查到 23 / C 明确结论但方向错 20 / B 只差说出口 2。→ "放宽差不多意思算过"最多 +2/45（基本没用）。
3. **换问法实验**（10 条非pass 改开放问法重跑）：约半数仍答不出（真检索边界），另半数**开放问法明显变好**（绝对化被修正、拒答变有内容）→ 强制 yes/no 二选一的形式本身会诱导过早结论；建议型解法="先按开放事实题作答，最后一步再裁决是/否"。

## 6. 决策与收口（边界账本）

- **停止**：不再做反复的 prompt 微调（外部裁判口径多轮几乎零净收益：75.5→75.0；LLM 单次波动即 ±2~3pt，"规则军备竞赛"无收敛点）。
- **② 类 = 模型能力**：想要就整链路换 `deepseek-v4-pro`（A/B 已验证有明确回收）——作为**选型**而非修 bug；pro 是独立的乘法轴。
- **① 类 = 唯一剩余工程方向**（含 1a/1b/1c），其中：
  - **MinerU 换解析层（1b，最大工程提升）**——暂缓，先做 spike（2~3 篇含表格重的论文试解析）再决定。已知风险/前提：保持 `parse_pdf→blocks` 接口不变；**表格内容只进 chunk 检索、不进 claims 提取**（防止复现"数值行拼伪 claim"的踩坑 1）；页码/heading/图表 caption 适配；模型权重体积与 CC BY-NC-SA 授权。
  - **检索策略（1a）**：收益未知，但 A/B 便宜（chunk 向量分钟级重建），可放 MinerU 之后做增量实验。
  - **1c（判太严被拒）**：紧邻 answer gate；可通过"先事实后裁决"与判分放宽缓解（仅 ~2/45 有效，收益小）。
- **模型现状**：`.env` 主链路 `deepseek-chat`（供应商侧对应 deepseek-v4-flash）；供应商可用模型：`deepseek-v4-flash` / `deepseek-v4-pro` / `deepseek-v4-flash-vision-exp`。裁判默认 glm-5.3（无余额，评测时须镜像主链路 key）。
