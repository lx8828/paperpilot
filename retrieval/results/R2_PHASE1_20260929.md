# Phase 1：把文献方法真正上到检索侧（2026-09-29）

> **背景**：前几轮一直在**修尺子**（自造指标 → 同源偏袒 → 真值锚点漏 43% → 本地 NLI 判定器不可用），
> **没上过任何优化方法**。本文件是第一次"文献方法 vs 现行基线"的实测对照。

## 0. 结论（两条）

1. **✅ 多查询（查询侧分解/扩展）有效**：k=10 时 **MRecall 0.114 → 0.229（翻倍）**、**StRecall 0.671 → 0.732（+6.1pt）**
   —— 这是 JPR/AMER 路线的**最便宜近似**（不需要训练新模型，只要多生成几条检索式）。
2. **❌ MMR（覆盖导向重排）无效，甚至有害**：所有 λ 在 k=5/10 上都劣于或等于基线。
   **原因：层级用错了** —— MMR 是**块级去冗余**，我们的目标是**篇级覆盖**；
   在"每篇都该被看到"的场景里，MMR 会把同篇的次要块挤掉、把无关篇的块提上来 → 反而降覆盖。

## 1. 实验设置

- 数据：3 簇 × 20 篇全文（缓存），**35 个 (簇, facet) 真值**（词面锚点口径，见 §4 边界）
- 多查询：用 `deepseek-chat` 为每个 facet 生成 **3 条互为补充的英文检索式**（48 次调用，缓存于 `subqueries.json`）
- 所有臂都产出**篇级排序**，按 k=5/10 截断，指标用标准口径（MRecall / StRecall / 集合P / α-nDCG）

| 臂 | 做法 |
|---|---|
| `A base` | **现行基线**：篇级分 = 篇内 max（dense 中文+英文词） |
| `B mq_max` | **多查询取最大**：4 条查询逐块取 max 后再取篇内 max |
| `C mq_rr` | **多查询 + 轮询聚合**（AMER 的 round-robin）：4 条排序交错，按首次出现定篇序 |
| `D mmr λ=…` | **MMR 重排**（λ=1.0/0.7/0.5/0.3；λ=1 等价于原排序） |
| `E mq_mmr λ=…` | 多查询融合分 + MMR |

## 3. 读法

- **`B mq_max` 全面最优**（k=10）：MRecall **翻倍**、StRecall **+6.1pt**、集合P 也小幅上升（0.511→0.540）。
  → 多查询同时改善了**召回**与**精度**，不是零和的。
- **`C mq_rr` 次之**：轮询保住了覆盖（+4.3pt），但因为它**强制每篇都进**，会把低分篇硬塞进来 → P 低于 B。
- **`D mmr` 全线无效**：λ 越小（越强调多样性）StRecall 越低（λ=0.3 时 −6.2pt）。
- **`E mq_mmr` ≈ 介于 B 与 C 之间**，没超过纯多查询。

## 4. 诚实边界

1. **真值仍是词面锚点**（实测 recall 仅 **0.567**，见 `R2_CALIB_20260928.md` A.5）
   → **绝对数偏低**，但**各臂用同一真值，横向比较有效**。
2. 35 个真值、单遍跑，**无显著性检验**（配对检验需要多遍或更多真值）。
3. 多查询只生成了 3 条（AMER 用固定 5 条嵌入）；**没调条数**，也没做"多查询 + 阈值化"的联合优化。
4. MMR 的失败**可能是实现细节**（在 40 块池上、用 cos 冗余）；但方向性理由（层级错配）是站得住的。

## 5. 下一步（按收益）

| 序 | 做什么 | 依据 |
|---|---|---|
| **1** | **多查询条数扫描**（1/3/5/8）+ **查询生成策略**（子面/同义/段落式） | B 是当前唯一有效方法，值得调透 |
| **2** | **多查询 + 判定环节（LLM 逐篇）**：多查询取块 → LLM 判"这篇做了吗 + 证据" | 判定环节才是产品必需的一环 |
| 3 | 覆盖率导向的**篇级配额**（每篇保底 b 块，再按篇级分截断） | = C 的改良，兼顾 P 与覆盖 |
| 4 | 用 **LLM 判定**当参考重算真值（修掉锚点漏 43%） | 绝对数才能对外说 |
