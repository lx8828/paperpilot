# C2a 收尾 + 方向修正：BM25 → BGE-M3 三路（Dense/Sparse/ColBERT）（2026-09-30）

本轮两件事：① C2a（BM25 通道注入）做完并**测出噪声底**；② 依据 C2a 的结论**放弃修 ASCII BM25**，
转向 BGE-M3 原生的 **Dense / Sparse / ColBERT** 三路。

---

## 1. C2a：BM25 通道注入

实现：`_r2_reader.py --bm25-b m` → 每篇证据 = 语义 top-6 ∪ **BM25 top-m**
（查询集与 dense 通道**完全相同** = 中文题面 + 3 条英文子查询）。

| 臂（b=6，同 28 题 / 同真值） | 集合P | 集合R | **集合F1** | prompt | 相对 |
|---|---|---|---|---|---|
| 基线（无注入） | 0.726 | 0.753 | **0.711** | 1,523,343 | — |
| 锚点注入 a=3（**dev-only 正则**） | 0.776 | 0.923 | **0.816**（3 次：0.800/0.824/0.825） | 1,599,682 | +5.0% |
| BM25 单独 m=1 | 0.770 | 0.866 | 0.792 | 1,625,341 | +6.7% |
| BM25 单独 m=3 | 0.743 | 0.875 | 0.779~0.786 | 1,879,640 | +23.4% |
| BM25 单独 m=6 | 0.727 | 0.904 | 0.784 | 2,288,590 | +50.2% |
| 锚点 + BM25 m=1 | 0.799 | 0.929 | **0.839**（3 次：0.846/0.838/0.834） | 1,680,751 | +10.3% |
| 锚点 + BM25 m=3 | 0.792 | 0.940 | 0.832（另一次 0.810） | 1,908,701 | +23.4% |
| 锚点 + BM25 m=6 | 0.770 | 0.916 | 0.810 | 2,307,262 | +50.2% |

### 1.1 ★ 噪声底（本轮最重要的方法学产出）

**同一配置重复 3 次的 F1 波动**：

| 配置 | 3 次 | 均值 | σ |
|---|---|---|---|
| 锚点 a=3（m=0） | 0.800 / 0.824 / 0.825 | 0.816 | **±0.013** |
| 锚点 a=3 + BM25 m=1 | 0.846 / 0.838 / 0.834 | 0.839 | ±0.006 |

→ **单次运行 σ ≈ 0.006~0.013**（F1 绝对值）。
→ **纪律：任何 Δ(F1) < 0.02 的结论，必须 n≥3 重复**，否则是噪声。
（本轮一度把 0.810 vs 0.832 当信号，后证实是噪声 —— 靠"prompt token 完全相同"露的馅。）

### 1.2 C2a 结论

1. ✅ **多通道有效**：BM25 单通道 0.779~0.792 vs 基线 **0.711** → +0.07~0.08（远超噪声）。
2. ❌ **但弱于人工锚点通道**：0.79 vs **0.816~0.821**。
3. ⚠️ **叠加很弱**：锚点 + BM25 m=1 = 0.839 vs 锚点单独 0.816 → **+0.023 ≈ 2σ**，边缘；
   m=3/6 不再涨甚至降 → **不是"两条独立通道"，是高度冗余**。
4. **m=1 就够**，m 越大越贵且无增益（+6.7% vs +50% prompt）。

### 1.3 ★★ 根因：中文题面 + 英文语料 → **字面词法通道结构上接不上**

- `_r2_std_metrics._tok` = `[a-z0-9]+` → **中文题面被整段丢弃**（真 bug）。
  已修（新增 `_tok_cjk`，CJK 二元组；`BM25(..., tok=)` 向后兼容），**但对本语料无效**：
  语料是英文 → CJK 词不在索引 → `scores()` 里 `idf.get(t) is None → continue`。
- **证据**：ascii 与 cjk 两次运行的 **prompt token 完全相同**（1,879,640）→ 注入了**同一批块**。
- 所以 BM25 通道实际只靠**3 条英文子查询**工作 = "对翻译版做词法检索"。
  而**锚点正则是英文正则、直接在英文语料上定位** → 这就是它更强的机械原因。

### 1.4 ⚠️ 三处**我说错了、已纠正**（2026-09-30 补查生产链路后）

| 我原先的说法 | **纠正后的事实** | 证据 |
|---|---|---|
| 「BM25 只靠**英文子查询**工作」 | ❌ **错**。子查询≈**零贡献**；BM25 主要靠**题面里嵌的英文触发短语** | `--subq-n 0`（去掉子查询）F1 **0.779** vs 带子查询 0.779~0.786，prompt 1,781,946 vs 1,879,640 |
| 「生产的 BM25 对中文 question **完全失效** → 混合检索实际是 dense-only」 | ❌ **错**。生产有 **L6 跨语言**（`query_optimizer.crosslingual`，**默认开**）：中文问 → 一条**英文检索式** → 与主路**加权交错**。实测 **gold@12 69.3% → 79.4%**、M1 篇全 16/20 → **19/20** | `agents/nodes/pull_chunk.py::search_l3` docstring（`retrieval/tmp/_sandbox.py --prod`，120 题） |
| 「生产的 BM25 中文硬伤」 | ⚠️ **部分成立**：`SparseBM25.TOKEN_RE = [a-z0-9]+` 确实丢中文 token；但**中文问句会照抄英文实体名/数字/缩写** → 实测 **120 题中 87% 的 BM25 有非零分**（`_lang_effect.py`）；缺的只是**动词/领域表述**，而那部分由 **L6** 补 | `retrieval/scripts/eval_retrieval.py` L44/L59；`query_optimizer._XLING_SYS` 注释 |

**由此得到一个重要的口径结论**：
> **dev 的 BM25 通道比生产"富"** —— dev 用「操作化题面（**人工嵌入英文触发短语**）+ 3 条**离线精炼**的英文子查询」；
> 生产只有「用户问句 + **1 条在线生成**的英文检索式」。
> → **dev 的 BM25 数字（0.78）对生产是乐观的**，与"锚点正则"属同类**同源偏袒**。

### 1.5 生产链路真实全貌（补查）

## 2. 方向修正：用 BGE-M3 原生的 Sparse / ColBERT

### 2.1 事实核实（全部已验证）

| 结论 | 证据 |
|---|---|
| **我们只用了 Dense** | 本地 `bge-m3/modules.json` = `Transformer → Pooling → Normalize`；权重 391 个张量中 **0 个** 含 `sparse`/`colbert`/`linear` |
| **BGE-M3 一次前向可出三路** | 官方 `BGEM3FlagModel` 返回 `dense_vecs / lexical_weights / colbert_vecs` |
| **头文件缺失，现已拿到** | 已下载 `sparse_linear.pt`（Linear 1024→1）、`colbert_linear.pt`（Linear 1024→1024，fp16） |
| **不需要 FlagEmbedding** | base encoder 本地已有（2.27 GB）+ 两个头可 `torch.load` 直接用；环境 `transformers 5.16.1` / `torch 2.14.0` |
| **已有重排资产** | `BAAI/bge-reranker-v2-m3` **已在本地**，且 RAG-1 里实测 **+6.56pt** |

### 2.2 为什么这比"修 BM25"务实

| | 修 ASCII BM25 | BGE-M3 Sparse |
|---|---|---|
| 中文 query ↔ 英文语料 | ❌ **结构上不可能**（字面 token 不重叠） | ✅ **学习型稀疏**：训练让"代码/code"落在**共享的词表维度**上 |
| 依赖 | 需要中文分词 + 翻译（我们靠子查询） | 一次前向，与 dense **共享编码** |
| 生产可用 | 需要改 tokenizer + 重建索引 | `sparse_linear` 只是 1024→1 的线性层 |
| 额外收益 | 无 | 顺带得到 **ColBERT 多头向量**（文档侧**可离线预算**） |

### 2.3 对用户方案的三点修正 / 补充

1. **ColBERT 重排 vs 已有的 CrossEncoder**：两者都值得试，但**应先复用 `bge-reranker-v2-m3`**
   （本地已有、已验证 +6.56pt、零新增）；ColBERT 的优势是**文档侧向量可离线算好**
   → 延迟低、可对更大候选集重排。**定位：CE = 精度上限参考，ColBERT = 可上生产的低延迟版。**
2. **Sparse 不能完全替代字面 BM25**：学习型权重对**数字/缩写/代码/数据集名**这类
   "dense 与 sparse 都可能弱" 的精确 token，字面匹配仍可能更稳。
   → 建议保留**三通道**：`dense + learned-sparse + 字面BM25(英文子查询)`，用 RRF 融合后**再重排**。
3. **必须带噪声纪律**（§1.1）：Δ<0.02 一律 n≥3 复跑。

## 3.5 ★ S1 结果（2026-09-30 已完成）

脚本 `_bge_m3.py`（自实现，**零新依赖**：本地 base encoder + 单独下载的两个头）。
验收命令：`./.venv/Scripts/python.exe -u retrieval/tmp/_bge_m3.py --smoke`

**实现**：`dense = normalize(CLS)`；`sparse = relu(Linear(h))` → 按 token id **scatter-max**；
`colbert = normalize(Linear(h))` 逐 token。加载 10.1s ｜ 8 条短文本编码 **0.04s**（cuda·fp16）。

### 3.5.1 验收 1：sparse 权重落点（块 = `Our code is available at https://github.com/thu-ml/LM-Calibration`）

| token | 权重 | 块内排名（共 43 个非零） |
|---|---|---|
| `▁reproduc`（reproducibility） | **最高** | 1 |
| `▁code` | 0.195 | **8** |
| `▁available` | 0.115 | 24 |
| `▁github` | 0.000 | —（tokenizer 未产出该 piece） |

→ ✅ **权重确实集中在信息实体/领域词上**（top-5 = `reproduc` / `lib` / `experiment` / `setup` / `LM`），
而非虚词 → 比原始 tf-idf 的"学习型词法"这一面成立。

### 3.5.2 ★★ 验收 2：跨语言核验（**决定性，且是负面结论**）

| query（× 同一英文块） | tok | **sparse** | dense | colbert | 共享 token |
|---|---|---|---|---|---|
| **① 纯中文**（无任何英文）「本文有没有公开自己的代码和数据」 | 10 | **0.000** | 0.541 | 5.2 | **0** |
| ② L6 英文检索式（**生产形态**） | 16 | 0.046 | 0.493 | 8.1 | 2 |
| ③ 题面英文短语（**dev 形态**） | 11 | **0.144** | 0.643 | 7.8 | 5 |

1. ❌ **BGE-M3 sparse 完全不能跨语言**：纯中文 query 的 sparse = **0.000**、**共享 token = 0**。
   机制已明确：`sparse_linear` 是 `Linear(1024→1)`，**每 token 一个标量**，匹配仍**按 token id 重合**
   （XLM-R sentencepiece ~250k）→ 中英 content word 的 id 不重合 → 分恒为 0。
   **"学习型稀疏能做跨语言词法"这一前提，实测不成立。**
2. ⚠️ **发现并修掉一个会让排序退化的坑**：特殊 token（`<s>` / `</s>` / `<pad>` / `<unk>` / `▁`）
   在英文块上**权重非零**，会让**任意 query（含纯中文）**拿到一个**近似常数**的分
   （修前纯中文 = **0.051**，全是 `<s>`+`▁`）→ **对排序只有稀释作用**。现已在 `encode(drop_special=True)` 中剔除。
3. ✅ **只有 dense 真正跨语言**：纯中文 0.541 ≈ 英文 0.493（比值 1.03）。
4. ⚠️ **colbert 部分跨语言**：向量本身是上下文化的（纯中文也有 5.2），但打分是**逐 token MaxSim 求和**
   → 与 query 长度相关，需并列 `colb/√n` 做长度校正才可比。
5. ★ **再次印证 §1.4 的口径结论**：③（dev 题面英文短语）sparse 0.144 **是 ②（生产 L6 检索式）0.046 的 3.1×**
   → **dev 的词法通道比生产"富"得多**（题面英文短语是贴着答案写的）。

### 3.5.3 对 S2/S3 的**设计修正**（必须改）

| 步 | 原计划 | **修正后** |
|---|---|---|
| **S2** | 召回对照：`dense` / `sparse` / `dense+sparse(RRF)` / `+字面BM25` | **sparse 通道的 query 必须是 L6 英文检索式**（生产形态），不能用中文题面 —— 否则 sparse 恒 0，对照无意义。且要**同时报 dev 口径（③）与生产口径（②）**两组数字 |
| **S3** | 重排：无 / `bge-reranker-v2-m3` / ColBERT | **不变**，且这是**跨语言的主要希望**：dense 语义 + CE 的 cross-attention 才能跨语言（ColBERT 亦须在中文 query 下单独验） |

**净结论**：用户方案里 **"ColBERT/CE 重排" 的价值不受影响**（是纯新增、且跨语言靠 dense+cross-attention）；
但 **"Sparse 召回解决跨语言" 这一理由被实测否掉** —— sparse 的价值回到
「**配英文检索式时，比 ASCII BM25 更好**（多语言分词 + 学习权重）」，而不是「替代跨语言」。

## 4. 边界

1. C2a 的"锚点通道"用了 **dev 侧人工正则**（同源偏袒）→ 0.816 是**上界参考**，不是可交付数字。
2. 上述所有 F1 均为 **28 题**、单次或 n=3；噪声 σ≈0.01（§1.1）。
3. L2/L3 的"证据/引用"仍用**锚点命中块**作代理（继承锚点偏差）。
4. Sparse/ColBERT 头是**下载**的（网络可用）；`FlagEmbedding` 未安装，故按 §S1 自实现。
5. 生产的 BM25 中文失效（§1.4）**本轮未修** —— 按 §S4 与 sparse 通道一起处理。
