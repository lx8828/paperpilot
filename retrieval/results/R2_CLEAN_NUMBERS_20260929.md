## 一、生产链路泄露审计（`qa/` + `cli/` + `src/paperpilot/`）

### A. 题面 vs 判分锚点（构造级泄露）——**大体干净**

398 道题 / 40 个题集文件：

| 项 | 均值 | 判定 |
|---|---|---|
| `must_all` 锚点个数 | 1.27/题 | — |
| **题面里已含的 `must_all` 锚点数** | **0.116/题** | ⚠️ 33 道（8.3%）题面含锚点 |
| `must_all` 词与题面 token 重合率 | 0.055 | 低 |
| `must_any` 词与题面 token 重合率 | 0.079 | 低 |
| **gold 引文与题面 token 重合率** | **0.000** | ✅ **题面完全不是照抄原文** |

**8.3% 那 33 道的性质**：几乎全是**专名指代**（题面说"SkillMAS 这篇…"、"AutoConcept 和另一方法谁更好"），
锚点出现在题面里是**指代**，正确答案是别的东西。**不是把答案抄进题干。**
→ 结论：**题面干净**（gold 引文重合 0.000 是最硬的一条）。仍建议对那 33 道做一次人工复核。

### B. 判分放水：`ok` vs `ok_strict`——**生产侧有 +0.12 虚高**

`cli/run_multi_qa.py::score_answer` 把**模型自己引用的证据原文**并进判分文本：

```267:271:cli/run_multi_qa.py
judge = answer
ev = [str(c.get("evidence") or "") for c in (cites or []) if c.get("evidence")]
if ev:
    judge = answer + "\n" + "\n".join(ev)
ok_judge, miss = keyword_ok(judge, all_, any_, [])
```

而锚点（数字/专名）本来就取自论文原文 → **模型只要照抄一段原文就能命中锚点**。

| 题类 | 运行数 | `ok`（含自引证据） | **`ok_strict`（仅答案·干净）** | 放水幅度 |
|---|---|---|---|---|
| 单篇题 | 15 | 0.845 | **0.699** | **+0.177** |
| 跨篇 M1/X5 | 39 | 0.591 | **0.489** | **+0.100** |

→ **干净口径 = `ok_strict`**（仓库已自带该字段，只是没被当作对外口径）。

### C. `hint`（=答案）是否进 pipeline——**干净，但有遗留风险**

- **静态**：`run_group_qa.py` L137 `graph_ask(question, corpus)`；`run_multi_qa.py` L500 `state={"question", ...}`
  → **只传题干 + 语料**
- **动态**：`src/` + `cli/` 的**非注释行**里读 `hint` 的位置 = **0 处** ✅
- ⚠️ **遗留风险**：`hint` 与 `must_all` **同处**于 runner 读的题集文件（`qa/multi/*.json`、`qa/questions/*.json`）
  → 任何新 runner 写一句 `q["hint"]` 就会瞬间满分。**建议在题集加载处显式剔除 `hint` 再交给 runner。**

### 2.2 R2 集合型检索（用户自带 20 篇语料，35 个真值）｜**干净打分 = `dense_zh`**

- **唯一可解读水位**：`StRecall@10 = 0.681`，相对随机约 **1.37 倍**

## 三·补｜gold 隔离守卫（2026-09-29 落地，堵 §一C 的遗留风险）

**改动**（`cli/run_multi_qa.py` + `cli/run_group_qa.py`）：

| 新增 | 作用 |
|---|---|
| `GOLD_KEYS` | gold-only 字段清单：`hint / evidence / must_all / must_any / must_have / must_not` |
| `gold_of(q)` | 显式取 gold（**只允许判分/诊断用**）|
| `assert_no_gold(obj, where)` | 边界守卫：pipeline 输入里出现 gold 字段 → **抛 AssertionError**（递归查嵌套）|
| `pipeline_state(question, corpus, **extra)` | **唯一许可**的 state 构造入口（自带 guard）|

**接入点**：`run_multi_qa` 的两条 state 构造（L0 分支合并 `l0_state` 后**再查一次**；检索分支改走
`pipeline_state`）+ `run_group_qa` 的 `graph_ask` 调用前。

「真实题集确实同时含 `hint` 与 `must_all`」（证明守卫在防真东西）、

## 五、边界

1. 生产泄露审计是**静态 + 数据侧**（题面↔锚点、判分文本构造、运行时读取面），**未做**"模型是否从引文里学答案"的动态实验。
2. `ok`/`ok_strict` 的对比**跨 15/39 个历史运行求均**，各运行的题集与配置不同 → 只能看**放水幅度**，不能当同一实验的 A/B。
3. 8.3% 的题面含锚点**未经人工判定**是否属真泄露。
4. 生产 `ok_strict` 的 0.699 / 0.489 **仍是"词面锚点判分"**，非人工判读 → 上界偏松。
