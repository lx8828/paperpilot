## 1. 为什么必须做这套审计（威胁模型）

LLM + 检索评测有六类典型失真，逐类防守：

| 威胁 | 典型症状 | 我们的检查 |
|---|---|---|
| T1 **口径错** | 自己重实现指标，与官方差一点 | 用官方 CLI 复跑 + 逐题对账 |
| T2 **数字水分** | 靠多列答案把 recall 刷上去 | 答案数/比值/precision 审计 |

| T4 **数据集污染** | 模型预训练见过该数据集 | 闭卷直答 + **半查询法** + 配对判别 |
| T5 **评分放水** | 判分文本里塞了模型自引的证据 | 口径审查（生产侧） |
| T6 **分母陷阱** | 空答案被剔除后指标虚高 | 口径审计 + 报数纪律 |

## 2. 口径正确性（T1）

### 2.1 用官方 CLI 复跑，逐题对账

- 官方包：`google-deepmind/loft`（`run_evaluation.py` + `evaluation/{rag,utils,loft_evaluation}.py`），已落到 `retrieval/data/loft/official/`

  产物落 `results/official_runs/<run>/{queries.jsonl, preds.jsonl, preds_metrics.json, preds_metrics_per_line.jsonl}`
- **重跑一致性**：对同一 `preds.jsonl` 重跑，**逐题 0 差异**（`A vs C 不一致题数：0`）

### 2.2 官方指标实现（逐行核对，非"以为"）

```python
# evaluation/rag.py  MultiValueRagEvaluation
em         = float(set(gold) == set(pred))                       # 集合相等
coverage   = len(set(pred) & set(gold)) / len(gold)              # ← 只有 recall
subspan_em = 双向子串(gold in pred or pred in gold) + 匈牙利分配 + 全对齐才 1
# 多值分支**没有 f1 赋值** → aggregate 取 defaultdict 默认 0.0（官方 f1 恒为 0）
```

预处理（`evaluation/__init__.py` + `utils.py`）：pred = `convert_to_str` → `normalize_answers`；
gold = `normalize_answer`（NFD → lower → 去标点 → 去冠词 → 空白归一）。**与我们的自实现同源。**

### 2.3 两套官方口径互证

另外移植 **HELMET/ALCE** 的 QAMPARI 官方指标 `eval_alce.py::compute_qampari_f1`
（输出 `num_preds / prec / rec / rec@5 / f1`）：

| 检验 | 结果 |
|---|---|
| ALCE 式 P/R vs 我们的集合式 P/R（12 个运行） | **P、R 全部差 0.000** ✅ |
| 自实现 em / coverage / subspan_em vs 官方 CLI | 逐位一致 ✅ |

### 2.4 F1 自检（用户提出的判据）

判据：F1 ≫ subspan_em 才合理；F1 ≪ subspan_em → subspan_em 实现可能有 bug。

同一份预测（`audit_k40_k40`，官方已验 subspan_em=0.69 / em=0.47 / coverage=0.8148）：

| 指标 | 均值 |
|---|---|
| `subspan_em`（官方主指标） | 0.6900 |
| subspan 覆盖率（逐 gold 匹配率） | 0.8943 |
| 严格集合 recall（=官方 coverage） | 0.8067 |
| 严格集合 precision | 0.8169 |
| **集合级 F1** | **0.7976** |
| **答案级 F1**（SQuAD 式） | **0.8883** |
| frac(严格 coverage == 1) | 0.5600 |

**→ F1（0.798 / 0.888）> subspan_em（0.690），符合预期** ✅

三重验证：
1. **7 项合成单元测试全过**：完美→1、少一个→0、**超集→1**（证明不看 precision）、**gold 被包在长句里→1**、全错→0、空→0、顺序打乱→1
2. **3 项内部一致性全过**：`subspan_em(0.690) ≥ frac(coverage==1)(0.560)`；`subspan覆盖率(0.894) ≥ 严格recall(0.807)`；`subspan_em − frac(subspan覆盖率==1) = −0.020`（互斥分配的合理压低）
3. **跨 12 个运行**：11 次满足 F1 > subspan_em

**唯一例外（已定位，属指标性质不是 bug）**：全库仅 **3/100 题**出现 `subspan_em > F1`，均为预测写成「**gold + 限定词**」：

| gold | pred | subspan_em | 严格 coverage/F1 |
|---|---|---|---|
| `friday 13th` | `friday 13th **2009 film**` | 1 | **0.00 / 0.00** |
| `rang` | `rang **2014 film**` | 1 | 0.40 / 0.40 |

→ 官方 `gold in pred or pred in gold` 的**双向子串**规则会奖励"更具体的答案"。

### 2.8 ★ 一个必须承认的点：**128k 档下"直读全档"与"检索"打平**

同一次核对暴露的问题——**本档语料（755 段 ≈ 105k token）可以整档塞进上下文**，所以：

| 运行 | 方式 | `subspan_em` | `em` | `coverage` |
|---|---|---|---|---|
| `direct128k_k20` | **整档直读**（755 段全给） | **0.700** | **0.490** | 0.799 |
| `exh_k40_k40` | **检索 top-40** | **0.700** | 0.440 | 0.8209 |

→ **subspan_em 完全相同（0.700），直读的 `em` 还更高（0.490 vs 0.440）**
→ **因此 0.700 不能归功于"我们的检索"**；在这个档位上，成绩主要来自 **reader + 提示（exhaustive）+ 语料本身可整档放入**。
→ 这与论文自己的发现一致（128k 上 LCLM CiC 0.44 ≈ pipeline 0.55 量级）。

**⇒ 真正能判决"检索值不值"的是 `1m` 档**：844k token 装不进常规上下文，检索必须创造价值；
且论文报告 1M 档上模型性能**下降**（Figure 5）。

**✅ 已跑（2026-09-29，见 `R2_QAMPARI_TIER1M_20260929.md`）**：
`1m` 档（5,878 段 ≈ 849k token）检索 top-40 → **`subspan_em` 0.380 / `em` 0.220 / `coverage` 0.5107**（128k 档为 0.700 / 0.440 / 0.8127）。
但**掉分主因不是检索召回**：`R@40` 仍 **0.954**（gold 段落 95% 在上下文里），
掉的是 **排序**（`R@5` 0.822→0.514、`MRecall@5` 0.470→**0.110**）与 **reader 长上下文退化**。
**单题铁证**：检索用 **0.7%** 上下文拿 **5/5**；直读用 **24%** 上下文只拿 **3/5** 且开始编造。
→ **1m 档下检索是决定性的**；下一步靶心从"更强召回"转为 **重排 + reader 抗噪**。

## 4. gold 泄露（T3）

用户要求逐项确认：① 索引与排序全程不用 gold 段落 ID；② "每篇保底轮询"只在检索结果上做；③ 多查询 prompt 里只有问题本身。

### 4.1 QAMPARI 线（本次主结果所在）

| 项 | 核查 | 结论 |
|---|---|---|
| **索引** | `C = enc.encode(corpus["full"])`，`corpus["full"] = title + passage`；BM25 语料同 | ✅ **gold 从未进入索引** |
| **排序** | `order = np.argsort(-score)`；score 由查询向量/BM25 算 | ✅ **gold 未参与打分** |
| **`qrels` 的使用** | 见下（时序证明） | ✅ **仅指标用** |
| **唯一 gold 进排序处** | `add_l1("oracle", ..., "完美排序（上界）")` | ⚠️ **显式标注为上界，不可部署** |

**时序证明**（`_qampari_run.py`）——读 gold 严格晚于排序，且只流向诊断指标：

```276:299:retrieval/tmp/_qampari_run.py
dense  = D @ qv[qi]                      # ① 打分
sparse = bm25(q["query_text"])
order  = np.argsort(-score)[:pool]       # ② 排序完成
...
qrels     = [str(x[0]) for x in q["metadata"]["qrels"]]   # ③ 之后才读 gold 段落 ID
gold_pass = set(qrels)
hit       = len(set(pid_of[i] for i in order) & gold_pass)
# ④ hit 只流向 recall_pass（诊断指标），不回流任何决策
```

### 4.2 净化对照实验（把"没有泄露"变成**可量化**的）

对 R2 线的锚点通道做了决定性实验：把查询里**与 gold 正则重合的词删掉**再测——

| 查询变体 | 篇级 AUC | Δ vs 干净基线 |
|---|---|---|
| `zh`（干净） | **0.702** | — |
| `zh+anchor`（污染） | 0.739 | +0.037 |
| `anchor`（最污染） | 0.776 | +0.074 |
| **`anchor` 净化后** | **0.694** | **−0.009** |
| `bm25_anchor`（污染） | 0.894 | +0.192 |

**→ 净化后优势归零甚至转负 ⇒ 那 +0.074 的 100% 来自泄露**（R2 线锚点词 **63%** 与 gold 正则同词）。
据此**撤回**了旧结论「加英文锚点词 +4pt / XLING 值 +4pt」。

> ⚠️ **本条不适用于 QAMPARI 线**：QAMPARI 的查询是数据集自带 `query_text`，**不存在我们自己造的锚点词**。
> 记录在此是为了说明：同类风险我们**会主动去找、会量化、会撤回结论**。

### 4.3 生产链路侧（hint 隔离）

生产题集里 **`hint`（=出题者摘录的答案原文）与 `must_all`（判分锚点）同处**于 runner 读取的 json。

| 核查 | 结果 |
|---|---|
| 运行时读 `hint` 的位置（`src/`+`cli/` 非注释行） | **0 处** |
| 题面 `question` 与 gold 引文 token 重合 | **0.000** |
| 题面里含 `must_all` 锚点的题 | 33/398（8.3%），**多为专名指代**（"SkillMAS 那篇…"），非抄答案 |

**但从"偶然安全"升级为"结构性安全"**（本次新增）：

| 新增 | 作用 |
|---|---|
| `GOLD_KEYS` | gold-only 字段清单（`hint/evidence/must_*/must_have`） |
| `assert_no_gold(obj, where)` | 边界守卫：pipeline 输入里出现 gold 字段 → **抛错**（递归查嵌套） |
| `pipeline_state(question, corpus, **extra)` | **唯一许可**的 state 构造入口（自带 guard） |
| `tests/test_gold_guard.py`（11 项） | 含「真实题集确实同时含 hint 与 must_all」（防空转）、「cli/ 非注释行不得读 hint」（静态钉死） |

**全量 `pytest -q` exit=0（无回归）**，lint 干净。

## 5. 数据集污染（T4）

### 5.1 探针设计（全部**不给任何文档**）

| 探针 | 设计 | 目的 |
|---|---|---|
| **P1 闭卷直答** | 同 `--exhaustive` 提示、零文档 | 模型本来会不会答 |
| **P2 半查询法** | 给题面前半 → 要求**逐字补全**后半 | 数据集**文本**是否被背下来 |
| **P3 半答案法** | 给 gold 一半 → 列出**其余**（留出集），含**盲猜基线** | 答案集是否被背下来 |
| P4 配对判别 | 真答案集 vs 干扰答案集，二选一 | 是否知道"题↔答案集"绑定 |

### 5.2 结果（100 + 60 题，340 次调用，¥0.635）

| 探针 | 结果 | 判读 |
|---|---|---|
| **P1** | `subspan_em` **0.150**（带检索 0.700）｜**`em` 0.000**｜precision 0.058｜预测数 **43.35** | ✅ **无数据集记忆** |
| **P2** | 逐字补全命中 **0.0%**（60/60） | ✅ **数据集文本未被复现** |
| **P3** | 留出召回 0.394，但**精度仅 0.091**、给 19.6 个（留出 2.0）；盲猜基线 0.000 | ⚠️ **世界知识 + 撒网**，非"知道答案集" |
| P4 | 同域 0.983 / **随机干扰 1.000**（差 −0.017） | ❌ **探针无效**（见 5.4） |

**最强证据**：若模型背下了 QAMPARI 的（题 ↔ 答案集）配对，**无文档时 `em` 不可能是 0.000**。

### 5.3 对已有数字的影响：给出**净增益口径**

| 指标 | 闭卷（无文档） | 带检索 | **检索净增益** |
|---|---|---|---|
| `subspan_em` | 0.150 | 0.700 | **+0.550** |
| `coverage` | 0.262 | 0.813 | **+0.551** |
| `em` | 0.000 | 0.440 | +0.440 |

→ **对外讲"我们的检索值多少"应报 +0.55，而非 0.700 绝对值。**

### 5.4 我们自己的探针缺陷（诚实记录）

| 缺陷 | 表现 | 修正 |
|---|---|---|
| **P4 构念效度错** | 首版拿 1.000，差点当成"记得数据集" | 加**随机干扰对照臂** → 两臂都 ≈100% ⇒ 该任务**靠语义拟合即可解**，**不能证明绑定** → **探针作废** |
| **P3 基线偏弱** | 从全体 gold 池随机抽，对"同域撒网"天然吃亏 | 明确标注 +0.394 是**世界知识的偏松估计**；用精度 0.091 否定"知道答案集" |
| **P1 提示不一致** | 首版用非 exhaustive 提示，与主运行不可比 | 改为同款 exhaustive 措辞 |

## 6. 分母陷阱与报数纪律（T5/T6）

### 6.1 官方 `coverage` 的分母会变

`coverage` 只在**非空预测行**上求均（空预测分支不写该字段）→ **空预测越多，coverage 越"好看"**：

| 运行 | 空预测 | coverage（官方报道） | coverage（全行口径） | em | subspan_em |
|---|---|---|---|---|---|
| **`exh_k40_ce_k40`** | **80** | **0.8600 ← 全表最高** | 0.1720 | **0.150** | **0.180** |
| **`exh_k80_k80`** | 74 | 0.8538 | 0.2220 | 0.180 | 0.180 |
| `exh_k40_k40`（主） | 1 | 0.8209 | **0.8127** | 0.440 | 0.700 |

→ **两次坏运行的 coverage 比主结果还高**，而 em/subspan 最差。

### 6.2 生产侧判分放水（`ok` vs `ok_strict`）

`cli/run_multi_qa.py::score_answer` 把**模型自己引用的证据原文**并进判分文本
（`judge = answer + cites[].evidence`），而锚点本就取自原文 → 照抄原文即可命中。

| 题类 | `ok`（含自引证据） | **`ok_strict`（仅答案）** | 放水 |
|---|---|---|---|
| 单篇题 | 0.845 | **0.699** | **+0.177** |
| 跨篇 M1/X5 | 0.591 | **0.489** | **+0.100** |

### 6.3 报数纪律（已固化）

1. **指标一律用官方 CLI 产出**，产物保留 `preds.jsonl`（可回溯）
2. **`coverage` 必须与「空预测题数 + em + subspan_em」同时出现**，禁止单独引用
3. **`precision` 用 ALCE 官方算术**，并**同时报 `num_preds`**（其口径更安全：空预测记 0、分母恒定）
4. **凡"检索增强"类运行，先看 `预测数 / gold 数` 比值**；>1.2 的标注"含多列水分"
5. **生产判分只用 `ok_strict`**
6. **区分绝对值与净增益**：对外讲检索贡献用"带检索 − 闭卷"

## 9. 已知边界（引用时必须带上）

1. **未见数据集污染，但只做了行为级探针**；未做成员推断（loss-based / 长片段逐字复现）。
2. **只测了 `deepseek-chat`**；换模型必须重跑污染检查。
3. **外部参照线（0.55 / 0.44 / 0.27 / 0.25）是别的模型**，是参照不是同条件对比。
4. **`coverage` 的全行口径更保守**，官方报道口径偏乐观（分母剔空预测）。
5. **`subspan_em` 的双向子串规则会奖励"更具体的答案"**（已量化 3/100 题）。
6. **P3 的 +0.394 是世界知识的偏松估计**（盲猜基线偏弱）；精度 0.091 已足以否定"知道答案集"。
7. **闭卷对照是两种提示制度**，"净增益 +0.55"是近似值，不是严格同条件 A/B。
8. 生产侧审计是**静态 + 数据侧**，未做"模型是否从引文里学答案"的动态实验。

## 10. 结论

在 **口径（官方 CLI 逐位复现）、水分（1.016× 无灌水）、泄露（索引/排序无 gold + 净化实验）、污染（`em` 0.000 + 半查询 0.0%）、分母（已量化并定纪律）** 五个维度上，
QAMPARI 主结果 **通过了检查**，可以作为对外数字引用。

**引用时的标准表述建议**：

> 在 **LoFT RAG / QAMPARI / `128k` 档**（官方 128k 档语料：**755 段落 ≈ 105k token**，100 题，
> 语料**保证含全部 gold 段落**）上，我们的检索 + `deepseek-chat` 取得
> **`subspan_em` 0.700 / `em` 0.440 / ALCE precision 0.830 / recall 0.813 / F1 0.806**，
> 全部指标由**官方评测脚本**产出并与自实现逐题对账一致；
> 相对论文参照线（同档位：专用 RAG 0.55、Gemini 1.5 Pro 直读 0.44）**高出 +0.15 / +0.26**。
> 其中 **0.150 来自模型闭卷知识**（无文档直答实测），故**检索的净贡献为 +0.550**；
> 污染探针未见数据集记忆（无文档时 `em` 为 0.000，半题面逐字补全命中 0.0%）。
>
> ⚠️ **边界**：该结果**限于 128k 档（105k token 语料、gold 保证存在）**；
> **不构成"能从全量维基（~25M token 量级）里找齐答案"的证据**——该设定**我们未测过**（LoFT 官方亦无此档）。
