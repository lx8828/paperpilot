`_r2_c3_w1_v2.py --k 30`（316s，575 次调用）｜ 产物 `R2_C3_W1_PAIRED.csv` + `R2_C3_W1_SWEEP_v{1,2}.csv`

## 做法（配对同批，控制 LLM 非确定性）
窗口构造里只有一项来自子查询 —— `desens`（防泄露后的子查询）：
```
sem_top = 该篇内  sim = bge-m3([中文论断] + desens) @ 块向量  的 top-3
```
`subqueries.json`(v1) 与 `subqueries_v2.json`(v2) **只差 3 个 facet** → 其余窗口**逐字节相同**。
1. 全部 28 facet × 50 篇重建两套窗口、**逐字节比较**（零 LLM）
2. 只对**真正变化的对**，用 v1/v2 窗口**各判一次**（A+B+第三轮，同批配对）
3. 未变的对沿用 v1 判果；两套标签各跑 k 扫描

**实测**：窗口真正变化 **137 / 1,400 对**（簇1 `case_study`、簇2 `prompt_eng`+`knowledge_distill`、簇3 `case_study`）
→ **只花 575 次调用（而非 2,940）**，构建耗 115s。

## ★★ 为什么 v2 反而更差？—— 一个反直觉但很说明问题的机制

v2 的修复目标是 **facet 诊断指标**：`knowledge_distill` 泄露 45.8%→25.0%、`case_study` 冗余 Jaccard 0.67→0.00、
`prompt_eng` 补上 0→3 条。**这些指标全都改善了，但判官端却变差。**

**机制**：窗口的 `sem_top` 是**要把"证据块"取给判官看**。而 v1 那些被判为"泄露"的子查询，
恰恰含有**判据里的英文示例词**（如 `we ablate`）—— 这些词**正是证据块里会出现的词**
→ v1 的语义检索**精准命中证据块**；v2 把子查询改写成"干净、泛化"的表述
（如 prompt_eng 的 *"The study systematically investigates how different instruction formulations..."*）
→ 检索到的是**泛泛的方法描述**而非**具体证据** → **把证据块挤出 top-3** → 判官判非。

### ★ 结论：「泄露」在两个语境下作用**相反**
| 语境 | 目标 | "泄露词"的作用 |
|---|---|---|
| **检索阶段** | 公平地找相关文档 | ❌ **有害**（等于把答案喂进查询，虚高指标） |
| **窗口构造** | 把**证据块**取给判官看 | ✅ **有益**（判据词 ≈ 证据词，精准定位） |

→ **两者不该共用一套子查询。**
- **检索阶段** → 用 **v2**（干净、可辩护）
- **窗口构造** → 应继续用 **v1**，甚至**可以更"泄露"**

## 裁定

| 项 | 结论 |
|---|---|
| **窗口构造用哪版子查询？** | **继续用 v1**（`subqueries.json`）—— v2 在 4/4 受影响 facet 与全部 5 个 k 上都更低 |
| 检索阶段 | 保持 **v2**（`subqueries_v2.json`）—— 那里泄露确实该修 |
| v1/v2 是否该统一 | ❌ **不该**（目标相反） |

## 边界（不要过度解读）
1. **只有 4 个组合受影响、仅 8 个判果翻转** → Δ−0.022 **统计上很弱**，不足以说"v2 显著更差"。
   但足以说：**没有任何证据支持为窗口换 v2**，而且**方向一致为负**。
2. 只改了 3 个 facet；其余 25 个 facet 的v1/v2 子查询**本来就相同**，与本次结论无关。
3. 未区分"v2 的哪一处改动"（补缺 / 去泄露 / 去冗余）各自贡献多少 → 若要做，可逐 facet 单独换。
4. 未测"窗口用更泄露的查询"（如直接用 `pat` 的原文 / `para`）→ 那是本结论指向的**下一个假设**。
