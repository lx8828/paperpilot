# 论断/证据语言路线实测（2026-09-28）

> **问题**：跨语言 NLI（中文论断 × 英文证据）是不是短板？**加一层翻译**能不能降低误差？还是干脆全用英文？

## 0. 直接结论（两条，第二条是自我修正）

1. **"加一层翻译误差更小" —— 不成立**（本规模、本领域下）：
   - **论断侧翻译**：跨语言模型上**显著变差**（AUC 0.722 → 0.617）；英文 NLI 上只微好（0.689 → 0.709）
   - **证据侧翻译**：**三种判定器一致变差**（0.722→0.650、0.689→0.633、0.576→0.505）
2. **⚠️ 我上一条的判断被推翻**：我说"跨语言是短板、英文论断更好"是**基于 10 例构造用例**；
   在 **1361 对**真实证据上，**中文论断 + 跨语言模型（xnli2m）的 0.722 是全部 12 组里最高的**。
   （又一次"样本量决定结论"的教训。）

---

## 1. 实验设计（控制变量）

- **证据对 1361 条**（正 563 / 负 798），覆盖 16 个 facet × 3 簇
- 正例 = 该篇论文里**含锚点的那一句**（+前一句）= 真实支持证据
  负例 = **同一篇**里不含锚点的块首句 = "拿错了证据"
  → **同一篇论文内部对比**，排除"论文主题差异"这个混淆因素（hard negatives）
- 判据 = `entail` 概率把正/负分开的 **AUC**（0.5 = 瞎猜）

## 3. 为什么翻译反而更差：**机翻在领域术语上严重失真**

真实抽样（同一 facet：中文题面 → opus-mt 机翻 → 我们的人工改写句）：

| 中文题面 | **机翻英文** | 人工改写句 |
|---|---|---|
| 报告了推理效率指标（时间 / 延迟 / 吞吐） | Logical efficiency indicators reported (time / delay / **vomiting**) | how much time or memory it takes to run the model |
| 报告了多次运行的方差或统计显著性 | Multiple **operational deviations** or **statistical highlights** reported | we repeat each experiment several times and report the variation |
| 给出了案例分析 | **I gave you a case analysis.** | we look closely at a few concrete examples from our system |
| 关注标注成本（用了廉价 / 自动标注） | Focus on the cost of labelling (**costful** / auto-labelling) | getting labels is expensive or hard so we look for a cheaper way |
| 做了消融实验（把方法拆掉一部分看效果） | **I've done a decomposition experiment.** | we remove or drop parts of the model and see how the results change |

→ "吞吐" → **vomiting**；"方差" → operational deviations；"显著性" → statistical highlights。
**我们的论断是"术语密集型短语"，机翻会把语义打散** → 与证据的语义匹配反而更差。

## 4. 两个反直觉但重要的发现

1. **"人工英文改写句"并不比中文论断好**（0.606 vs 0.722 on xnli2m；0.709 vs 0.689 on fever）
   → 说明**跨语言 NLI 的"弱"被夸大了**（至少 mDeBERTa-v3-base-xnli 在 100 语言上对齐得不错）；
   而"改写句"与论文**实际措辞**差异大（论文可能写 "we ablate each component"，改写句写 "we remove or drop parts"），
   **反而降低了字面-语义的匹配**。
   → **结论：没有必要引入"英文论断"这一层**（机翻不行；LLM 生成未见得更好，且多一层复杂度）。
2. **绝对 entail 概率普遍偏低**（正例也只有 0.12~0.52）→ **base 级 NLI 在科学文本上置信度低**
   → **阈值必须重新校准，不能用 0.5**（ALCE 用的是 11B 的 TRUE，我们只有 279M）。

## 5. 结论与建议

| 决策 | 结论 |
|---|---|
| 论断语言 | **保持中文**（0.722，最高） |
| 证据语言 | **保持英文原文**（翻译一律变差） |
| 判定器 | **`MoritzLaurer/mDeBERTa-v3-base-xnli-multilingual-nli-2mil7`**（12 组最高） |
| 翻译层 | **不引入**（论断侧/证据侧都不加） |
| 阈值 | **必须校准**（绝对分低、跨 judge 不可迁移） |

**真正的瓶颈不是语言，而是 NLI 本身**：最好也只有 **AUC 0.722**，离"可用判定器"还远
（ALCE 用 11B 的 TRUE，且自报准确率只有 85.1%/77.6%）。所以优先级应该是：

1. **NLI 校准**（人工标注 40~60 对：支持 / 部分支持 / 不支持 / 说反了）→ 定阈值、量误差
2. **用 xnli2m 重算 L3（ALCE 引用指标）**，与词面代理的 `cite_recall=0.33` 并排 → 量化"同源偏袒"
3. 若校准后 AUC 仍 < 0.8，再考虑 **上更强判定器**（如项目已有的 LLM API 作 judge）

## 6. 边界

1. 正/负例是**自动构造**的（正=含锚点句，负=同篇不含锚点句），不是人工判断的 → 只能用于**相对比较**，不能当绝对精度。
2 . 机翻只测了 `Helsinki-NLP/opus-mt-*`（315MB 小模型）；**换个更强翻译器（NLLB-600M / LLM）结论可能不同** —— 但那就必须再做一轮，不能假设。
3. 人工改写句只有 19 条（每个 facet 一条），覆盖窄。
