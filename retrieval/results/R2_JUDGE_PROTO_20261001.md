# 判官协议成本对照：**双判官是纯浪费，改单判官省 52% 且质量不变**（2026-10-01）

`retrieval/tmp/_r2_judge_cost.py`（**零新 LLM 调用**，纯读已有逐篇 `A/B/third` 记录）
→ `results/R2_JUDGE_PROTO.csv`

**数据源**：`R2_PROD_FINAL_DELIV.csv`（上轮评估时把**全部候选篇**的 `label/A/B/third/rank/in_gold`
都落盘了）→ 于是几种判官协议可以**离线**比较，不必重跑。

实测基础：1,400 篇-题记录 ｜ A/B **分歧 201（14.5%）** ｜ A=unclear **14（1.0%）** ｜ B=unclear **0**

## ★ 结论：**双判官 + 第三轮在当前数据上收益为 0，纯花一倍调用**

1. **`onlyA` ≈ `cur`**（F1 0.718 vs 0.717）→ **B 与第三轮对最终交付集合的净影响 ≈ 0**
   调用 **2.10 → 1.00（省 52%）**
2. **机理**：B（裁判模型）**系统性更保守** —— `onlyB` 的 R 只有 **0.461**（vs A 的 0.775），
   `strict2`(AND) 的 R 0.454 ⇒ **B 带来大量假阴**。第三轮的作用**主要是把 A 的判果恢复回来**
   ⇒ 一正一负抵消。
3. **`strict2` 的 P 最高（0.777）** —— 但那是靠**砍掉 45% 的召回**换来的，F1 反而最低档。
   ⇒ 想提精度**不该**靠加固判官，应靠**改进窗口/召回**（R 才是瓶颈）。
4. `condA`（只对 unclear 补 B）**几乎等价**（F1 0.712，调用 1.01）—— 比 `onlyA` 还略低，
   因为 unclear 仅 1.0%，触发太少，省不到什么，还引入了 B 的保守偏差。

⇒ **建议：`PAPERPILOT_SET_DUAL=0`（纯单判官 A）。延迟与成本直接减半，质量不变。**

⚠️ **边界**：
- 本结论**建立在当前窗口/检索配置上**；换了窗口或判据口径需复测。
- B 是否在**别的**模型/提示词下更有价值，未测（当前 B = `PAPERPILOT_JUDGE`）。
- 单判官**失去了交叉校验**：若 A 有系统性偏差（如某类 facet 恒判宽），现在无人纠。
  本次数据显示这类偏差**不是瓶颈**（R 0.775 已高于双判官），但换语料应重测。

# 附：抽两道题实跑时发现的**生产健壮性问题**（2026-10-01）

跑 `retrieval/tmp/_r2_demo2.py`（抽 `c1|significance` + `c2|error_analysis`）时，
Q1 单判官交付 7 篇（F1 0.857），双判官交付 8 篇（F1 0.933），差集正是 `C1P6`。
**初步看像"协议差异"，实为一次瞬时 API 失败。**

## 证据

`set_judge.judge_one` 对 `LLMError` **不重试**，直接返回：

```python
except llm.LLMError as e:
    return {"label": "unclear", "extract": "", "evidence": [], "why": f"调用失败: {e}"[:60]}
```

该分支**不含 `A`/`B` 键** → `run()` 落档时 `verdicts[p]["A"] = ""`。
于是 **`A == ""` 就是"这次调用挂了"的唯一指纹**（其余任何路径都只会产出
`yes|no|unclear|err`）。据此统计 `R2_PROD_FINAL_DELIV.csv`：

| 项 | 值 |
|---|---|
| 总记录 | 1,400 篇-题 |
| **`A == ""`（调用失败 → 被判强制 `unclear`）** | **9（0.64%）** |
| `A` 取值分布 | `no` 1009 ｜ `yes` 368 ｜ `unclear` 14 ｜ **`""` 9** |
| 仅 `B` 为空 | 0 |

`C1P6` 在**记录的那次运行**里是 `rank=11 / label=yes / A=yes / B=yes / in_gold=1`
（即 F1 0.933 的那次）；本次单判官运行中它的 A 调用抛错 → `unclear` → 不交付 → F1 0.857。

## 影响与建议

**每失败 1 次调用 = 静默丢 1 篇交付**（`unclear` 不计入交付集合），
而交付集合是**召回**的来源 → 0.64% 的调用失败率会**稳定吃掉约 0.6% 的召回**，
且**完全无日志**（`.err` 里看不到，只有 CSV 里那个空字符串）。

- 建议（未实施，本次仅报告）：`judge_one` 对 `LLMError` **重试 1~2 次**（退避），
  或至少把 `A==""` 的篇**打日志**，让失败可见。
- 与主结论无关：`onlyA vs cur` 的离线对照用的是**同一份 A 判果**，不受此影响，
  "单判官 ≈ 双判官"的结论**仍然成立**。
