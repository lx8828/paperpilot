# 判定器校准（2026-09-28）：**NLI 不可用 → 改用 LLM judge**

> **一句话**：本地 279M NLI 在本任务上**基本不可用**（最优 F1 **0.653**、`contradiction` **100% 误判**）；
> **LLM judge（项目已有独立裁判 `glm-4-flash`）明显更可信**。
> **顺带量到真值质量**：词面锚点 **precision 0.947 / recall 0.600**（真值偏严、漏 40%）。

---

## 0. 先记录上一轮的三个方法学错误（已修正）

| # | 错误 | 后果 |
|---|---|---|
| 1 | **截断不一致**：LLM 看 1200 字、NLI 看 1800 字 | 两者看的**不是同一段文本**，比较无效 |
| 2 | **锚点被截掉**：48 行里 **32 行"构造=支持"的证据里搜不到锚点词** | 双方都在"对空气打分" |
| 3 | **抽样按 NLI 分数分层**（高/低各半） | 人为放大分歧，**不能用来量精度** |

**本轮修正**：证据 = **单块 b=1（1000 字，不截断）**，LLM 与 NLI 看到**完全相同**的文本；
抽样 **按类随机**（`块内含锚点` 30 条 + `不含` 30 条）。

## 1. 结果（60 条，b=1）

**判定分布**

| 判定器 | 分布 | 三分类完全一致率 |
|---|---|---|
| **LLM**（glm-4-flash） | neutral 38 ｜ entail 19 ｜ partial 3 ｜ **contradict 0** | — |
| **NLI**（mDeBERTa-xnli-2mil7, 279M） | entailment 39 ｜ neutral 12 ｜ **contradiction 9** | **0.433** |

**① NLI 阈值校准**（正类 = LLM 判 `entail`，19/60）

| 阈值 | TP | FP | FN | precision | recall | F1 |
|---|---|---|---|---|---|---|
| 0.3 | 17 | 26 | 2 | 0.395 | 0.895 | 0.548 |
| 0.5 | 17 | 21 | 2 | 0.447 | 0.895 | 0.596 |
| **0.7** | 16 | 14 | 3 | 0.533 | 0.842 | **0.653 ← 最优** |
| 0.8 | 14 | 10 | 5 | 0.583 | 0.737 | 0.651 |
| 0.9 | 9 | 7 | 10 | 0.562 | 0.474 | 0.514 |

→ **最优 F1 只有 0.653**：每报 2 个"支持"，就有 1 个是假的。**不足以支撑产品级引用判定。**

**② 真值质量（词面锚点 vs LLM）**

| 构造标签 | entail | neutral | partial |
|---|---|---|---|
| **不支持**（30） | **1** | 29 | 0 |
| **支持**（30） | **18** | 9 | 3 |

→ 锚点 **precision 0.947**（"不支持"里几乎不会误判成 entail）
→ 锚点 **recall 0.600**（"支持"里只有 60% 被 LLM 认可，另 10% 只是 partial）
→ **含义：我们的 gold 篇定义偏严、漏掉约 40% 的真支持** → **之前所有篇级/证据级数字都偏低**。

**③ `contradiction` 完全不可用**

- NLI 报矛盾 **8 条** → LLM 分布 **neutral 8**、认同率 **0.000**
- LLM 判 contradict 的条数 = **0**
→ 上一轮那个"13.5% 论断被说反了"**是 NLI 的误判，不是真发现** → **该指标作废**。

**④ 分歧样本（16/60）——双方都错，但错法不同**

| 论断 | 证据（节选） | NLI | LLM | 谁对 |
|---|---|---|---|---|
| 该论文讨论了安全/公平/偏见问题 | "…diverse **social bias**, **gender sensitivity** chinese, muslim **violence bias**…" | **0.955** | neutral | **NLI 对**（LLM 漏了 bias 词列表） |
| 该论文做了微调训练 | "…further **fine-tune** an RC model, using the NQ-trained weights…" | 0.057 | **entail** | **LLM 对** |
| 该论文做了消融实验 | "**Ablation Study** Here we **ablate** the properties of MuRAG…" | 0.135 | **entail** | **LLM 对**（NLI 在明摆着的文本上给了 0.135） |
| 该论文公开了代码或数据 | "Table 5: MMLU individual task performance…" | 0.997 | neutral | **LLM 对** |
| 该论文用了知识蒸馏 | 参考文献列表里含 "…algorithm **distillation**…" | 0.750 | neutral | **LLM 对**（且"支持"标签本身错——引用别人论文≠本文用了） |

## 2. 两条**撤回**（必须写下来）

1. **撤回"NLI 口径下 cite_recall 是 0.575~0.654"** —— 判定器不可用，那些数字作废。
2. **撤回"`b=1` 就饱和、证据给 1~3 块就够"** —— 那个结论来自 NLI 口径，同样作废。
   （词面口径下 b↑ 时证据召回确实涨：0.380→0.553，所以 **b 的最优值需重新校准**。）

## 3. 决策：判定器用 **LLM**，不用本地 NLI

| 项 | 决策 | 理由 |
|---|---|---|
| 判定器 | **LLM judge（`PAPERPILOT_JUDGE`，独立于主链路）** | 理由与证据内容吻合；本地 279M NLI F1 仅 0.65 |
| 成本 | 60 次调用实测 **≈620 prompt token/次**（上轮 48 次 = 29,721 prompt token）→ **每题 20 篇 ≈ 1.2 万 token，可忽略** | 与"逐篇 map"的既定设计同量级 |
| NLI | **保留但降级为"离线粗筛/无成本预过滤"**（若将来有 11B TRUE 再谈） | 它便宜，但结论不可信 |
| `b` 默认值 | **暂定 3**，但**标注"待校准"** | 词面口径下 b 影响证据召回；LLM 判定成本随 b 线性增长 |
| `contradiction` | **作废**（等 LLM 判定重算） | 本地 NLI 100% 误判 |

**为什么这反而是好事**：判定环节回到 **LLM**，正是你最初的设计（"返回块级 + 调用 LLM 的总结回答"）；
本地 NLI 这条路我们**用 60 条样本 + 一次方法学纠错就排除了**，代价极小。

## 4. 下一步

| 序 | 做什么 | 说明 |
|---|---|---|
| **1** | **用 LLM 判定重算 L3（ALCE 引用指标）** | 替代作废的 NLI 口径；成本同"逐篇 map" |
| **2** | **用 LLM 判定重算篇级标准指标**（MRecall/StRecall 的对照） | 顺便修掉锚点 recall 0.60 带来的"真值偏严" |
| **3** | 扩校准集到 150~200 条（仍是 LLM 标 + 人工抽查 20 条） | 60 条只够看方向 |
| 4 | `b` 默认值用 LLM 判定做一次 b∈{1,3,6,12} 对照 | 决定成本/召回折中 |

## 5. 诚实边界

1. **LLM 也不是金标**（上面第 4 条它就漏了 bias 列表）→ 结论是"**LLM 比 279M NLI 可信**"，不是"LLM 正确"。
2. 60 条样本，**只够看方向**；`partial` 只有 3 条，四档体系实际退化成两档。
3. LLM 用的是**独立裁判模型**（异源），避免同模型自证偏好；但仍是"机器校机器"，**理由已留档可抽查**。

# 附录 A：NLI 审计（2026-09-29）——"到底是 NLI 错还是 LLM 错"

> **触发**：用户质疑"你用 glm-4-flash 当参考，它也不强，凭什么说 NLI 错？"
> **结论**：**是 NLI 的问题**；且已用更强的 `deepseek-chat` 复标，结论不变、更稳。

## A.1 我们用的 NLI 清单与量级（回答"是什么、什么量级"）

| 模型 | 规模 | 底座 | 训练数据 |
|---|---|---|---|
| `MoritzLaurer/mDeBERTa-v3-base-xnli-multilingual-nli-2mil7`（**主用**） | **279M** | `microsoft/mDeBERTa-v3-base`（DeBERTa-v3 多语言版，CC100 多语言预训练） | multilingual-NLI-26lang-**2mil7**（200 万对 / 26 语言）+ XNLI |
| `MoritzLaurer/mDeBERTa-v3-base-mnli-xnli` | **279M** | 同上 | XNLI（15 语言）+ MNLI |
| `MoritzLaurer/DeBERTa-v3-base-mnli-fever-anli` | **184M** | `microsoft/deberta-v3-base`（英文） | MultiNLI + **FEVER** + ANLI（763,913 对） |
| `cross-encoder/nli-deberta-v3-base` | **184M** | 同上 | SNLI + MNLI（MNLI-mismatched 90.04） |
| **参照：ALCE 用的 `TRUE`** | **T5-xxl = 11B** | T5 | SNLI/MNLI/FEVER/**SciTail（科学文本）**/PAWS/VitaminC |

→ **我们比 ALCE 的判定器小 40~60 倍，且训练数据里没有科学文本**。

## A.2 先排除"是我用错了"（三个假设逐一验证）

| 假设 | 验证 | 结论 |
|---|---|---|
| **fast tokenizer 有 bug**（模型卡 "Debugging and issues" 提到 DeBERTa-v3 tokenizer 问题） | `use_fast=True` 与 `False` 都是 `DebertaV2Tokenizer`，169 token、回译一致、**预测逐位相同** | ❌ **排除** |
| **输入/标签顺序搞反** | 按模型卡 `tokenizer(premise, hypothesis)` + `id2label` 映射（`{0:entailment,1:neutral,2:contradiction}`） | ❌ **排除** |
| **跨语言用法不对**（中文论断 × 英文证据） | **控制实验**：同 60 条把论断换成**人工英文改写句**（只改语言） | ❌ **排除**，且方向相反（见下） |
| （我确实犯的错）**英文专用 NLI 配中文论断** | `fever` / `nli_ce` 是英文模型，中文 hypothesis 对它们是 OOD | ⚠️ **承认**：早前那两行比较无效 |

**控制实验结果**（参考 = deepseek 判定）：

| 模型 | 论断语言 | 最优阈值 | P | R | **F1** |
|---|---|---|---|---|---|
| xnli2m | 中文论断 | 0.7 | 0.467 | 0.737 | **0.571** |
| xnli2m | **英文改写论断** | 0.7 | 0.667 | 0.211 | **0.320**（Δ **−0.251**） |
| fever | 中文论断 | 0.3 | 0.294 | 0.263 | 0.278 |
| fever | 英文改写论断 | 0.3 | 0.400 | 0.105 | 0.167（Δ −0.111） |

→ **换成英文后反而更差** → **不是跨语言问题，是 NLI 能力不足**。

## A.3 决定性证据：两个**独立** LLM 高度一致，NLI 与两者都不一致

| 对比 | 一致率 |
|---|---|
| **glm-4-flash vs deepseek-chat**（异源、异构） | **0.900**（54/60） |
| NLI vs glm-4-flash | 0.433 |
| NLI vs deepseek-chat | 0.400 |
| 两个 LLM 一致时，NLI 是否也同意 | **0.593** → **22/54 条与"双 LLM 共识"相反** |

**NLI 阈值 vs deepseek**（更严格、更准的参考）：最优 F1 仅 **0.571**（阈值 0.7）。

## A.4 人工可裁定的个案（只读证据即可判断，不依赖任何模型）

| 论断 | 证据要点 | NLI | flash | deepseek | 裁定 |
|---|---|---|---|---|---|
| 做了消融实验 | "**Ablation Study** Here we **ablate**…" | **0.135** | entail | entail | **NLI 错** |
| 公开了代码或数据 | "Table 5: MMLU individual task performance" | **0.997** | neutral | neutral | **NLI 错** |
| 公开了代码或数据 | 参考文献 "Chinese Discourse Treebank…LDC" | **0.826** | neutral | neutral | **NLI 错** |
| 公开了代码或数据 | "…datasets … are all publicly accessible" | 0.996 | entail | entail | 三方皆对 |
| 讨论了安全/公平/偏见 | "…diverse social bias, gender sensitivity…"（**任务清单**） | **0.955** | neutral | neutral | **NLI 偏宽**（列任务名 ≠ 讨论偏见） |
| 讨论了安全/公平/偏见 | "…challenges…**bias and toxicity** in language models" | 0.840 | entail | entail | 三方皆对 |

→ **NLI 的主要错法是"把无关文本判成 entail"（假阳性 0.826~0.997）**，偶发"明写关键词却判低分"。

**NLI 的 `contradiction` 100% 是误判**：报矛盾 8 条 → deepseek 全为 neutral（7）/entail（1）；
两个 LLM 判 contradict 的条数均为 **0**。

## A.5 更新后的数字

| 指标 | 旧（glm-4-flash 参考） | **新（deepseek 参考）** |
|---|---|---|

| 词面锚点 recall | 0.600 | **0.567**（**真值漏 ~43%**） |
| NLI 最优 F1 | 0.653 | **0.571** |

## A.6 决策（修订 §3）

| 项 | 决策 |
|---|---|
| 判定器 | **`deepseek-chat`**（主链路那个；实测 34041 prompt token / 60 次 ≈ **567 token/次**） |
| **不要**用 | `glm-4-flash`（裁判模型）作参考标注 —— 它在"本文做的 vs 引用他人"上会判错 |
| 本地 NLI（184~279M） | **弃用**；要用 NLI 须上 11B 级（TRUE）或科学文本微调版（本机 6.4GB 显存放不下） |

# 附录 B：LLM 判定"够不够好"（2026-09-29，加入推理模型当裁判）

> **问题**：glm-4-flash 与 deepseek-chat 都属"小/中"量级，凭什么说 LLM 判定可用？
> **做法**：加入 **`deepseek-reasoner`（R1 推理版）** 作第三方裁判，同一批 60 条。**60/60 全部有效**。

## B.1 三条硬证据

**① 三个异源 LLM 互相高度一致，NLI 与所有 LLM 都不一致**

| 对比 | 一致率 |
|---|---|
| glm-4-flash vs deepseek-chat（异厂商异架构） | **0.900** |
| **deepseek-reasoner vs deepseek-chat** | **0.900** |
| deepseek-reasoner vs glm-4-flash | 0.817 |
| **NLI vs deepseek-reasoner** | **0.383** |
| NLI vs deepseek-chat | 0.400 |
| NLI vs glm-4-flash | 0.433 |

**② 以"两个较强 LLM 一致"为金标（54/60，覆盖 90%）**

| 判定器 | precision | recall | F1 |
|---|---|---|---|
| glm-4-flash | 0.889 | 0.889 | **0.889** |
| **NLI@0.7（最优）** | 0.500 | 0.722 | **0.591** |
| NLI@0.9 | 0.692 | 0.500 | 0.581 |

**③ `contradiction` 能力存在，但**极罕见**（不是 NLI 说的那样）

- `deepseek-reasoner` 全程只判出 **1 条** contradict（**1.7%**）
- NLI 报了 **9 条**（**15%**）→ 相差约 **8 倍**（NLI 的那些全被三个 LLM 判为 neutral/partial）

## B.2 成本

| 判定器 | 60 条消耗 | 折合 |
|---|---|---|
| `deepseek-chat` | prompt 34,041 / completion 2,208 token | ≈ **567 prompt token/次** |
| `deepseek-reasoner` | prompt 36,465 / completion 17,517 token | ≈ 608 prompt token/次 |
| （本地 NLI） | 0 API 成本，但 F1 只有 0.59 | 便宜但不可用 |

→ 1 题（20 篇逐篇判定）≈ **1.2 万 prompt token**，可忽略。

## B.3 为什么**不**换更大的 NLI（结构性理由）

1. **实测不是"大小"问题**：4 个 NLI（184M / 279M）F1 全在 0.57~0.65 同一档 → 再大一号（如 DeBERTa-v3-large ≈435M）预计仍在同档。
2. **任务性质不匹配**：本任务要判"**这篇论文自己做了 X，还是只在引用/列举别人的工作**"——
   这是**归属（attribution）判断**，而 NLI 的训练数据（MNLI/XNLI/SNLI）里没有这类监督信号。
   （个案可见：证据含 `(Pires et al., 2019)` / `(Köpf et al.)` 时，两个 LLM 判 neutral、"本文没做"，NLI 判 entail。）
3. **唯一够用的 NLI 是 ALCE 的 `TRUE` = T5-xxl（11B）**：fp16 需 ~22GB 显存（本机 **6.4GB**），
   下载 22GB 按实测 ~3.8MB/s 需 **~1.6 小时**，且仍未针对中文论断微调。

**→ 决策：判定器统一用 LLM（`deepseek-chat` 为主；可疑样本可用 `deepseek-reasoner` 复核），不再使用本地 NLI。**
