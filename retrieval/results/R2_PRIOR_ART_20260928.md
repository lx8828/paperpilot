# 新 RAG-2 · 先验工作与定位（2026-09-28）

> **一句话**：我们想做的"**给定一批论文 → 哪几篇做了 X → 给出块级证据 + 总结**"，
> 学术上叫 **multi-answer retrieval / set retrieval（多答案检索）**，2021 年就有正式定义与指标，
> 2025-2026 有 SOTA 方法与专门的覆盖度基准；工程上就是**系统综述的文献筛选（screening）**；
> 产品上 Elicit / NotebookLM / PaperQA2 已做出来。
> **我们的价值不在发明范式，而在：把"用户自带小语料 + facet 存在性判定 + 完备性声明"这条端到端串起来。**
> **顺带**：我们前几轮自己测出来的四条结论，文献里都有名字——**该改用现成指标，而不是自己造。**

---

## 1. 任务：它叫 multi-answer retrieval（多答案检索）

**JPR: Joint Passage Ranking for Diverse Multi-Answer Retrieval**（Min et al., 2021, UW + Google, arXiv:2104.08445）
—— 首次正式定义该任务与指标：

| | 单答案检索 | **多答案检索** |
|---|---|---|
| 训练数据 | $(q, a)$ | $(q, \{a_1…a_n\})$ |
| 评测 | Recall$(a, \{p_1…p_k\})$ | **MRecall$(\{a_1…a_n\}, \{p_1…p_k\})$** |
| 该用什么模型 | $P(p_i \mid q)$ | **$P(p_1…p_k \mid q)$** ← 联合打分，不是逐段独立 |

**核心论点**：两种任务推理接口相同，所以以前都用独立打分；但多答案检索的**本质是"不要重复召回同一个答案的段落、而要覆盖其他答案"**。
→ **这就是我们上一轮说的"排序式（top-k）vs 集合式（覆盖）"** —— 2021 年已经论证过，我们不用再自证。
- JPR 效果：多答案问题上优于稠密检索 **+11~12pt**、优于**独立重排器** **+6pt**（MRecall@k，全数据集一致）。
- 反例（Table 6）：问"Roseanne 里谁演 Mark？"→ 独立打分反复召回 Glenn Quinn 的段落、漏掉 Ames McNamara。

**AMER: Beyond Single Embeddings: Capturing Diverse Targets with Multi-Query Retrieval**
（Chen, Liu, Ravfogel, Choi；NYU；arXiv:2511.02770，**2025-11-04**）—— 目前最新的一条线：
- **诊断**：单查询向量**无法拟合多峰目标分布**（bi-encoder 用一个向量拟合所有正例簇）。
  随目标文档间距离增大，Contriever/Stella/Inf-Retriever/NV-Embed-v2 全部下降；换更强模型也救不了。
  → **这正是我们测到的"dense 中文题面篇级 AUC 只有 0.702 / 覆盖率低"。**
- **方法**：查询编码器自回归**逐个生成多个查询嵌入**（匈牙利匹配训练 + scheduled sampling），
  各嵌入分别检索后按 **round-robin 轮询聚合**。
  → **"轮询聚合"就是我们的"每篇保底 / 配额"** —— 已经有人做，且是 SOTA 的一部分。**我们别自己起名。**
- **效果**：QAMPARI +21.35%（**低相似度子集 +144.74%**）；AmbigQA +4.18%；合成数据上 4 倍提升。
- **⚠️ 一条对我们很重要的批评**：真实基准里同一查询的 gold 文档彼此很像（AmbigQA 余弦 **0.90**、QAMPARI **0.86**），
  跨查询随机文档只有 0.77/0.74 → **"现有基准对检索多样性的评测不足"**，作者呼吁更好的基准。
  → 我们的"同主题 20 篇 + facet 判定"正好落在这个空白上（但要注意：**我们的 gold 也可能彼此太像 → 题集偏易**）。

**QAMPARI**（Amouyal et al., 2022, arXiv:2205.12665）：答案是一个**实体列表、分散在多段落**；平均 **13 个答案/题**；
retrieve-and-read 最好 **F1 仅 32.8** → **列举式任务本身就是硬任务**（我们的水位要和这个量级对照着看）。

## 2. 覆盖度指标：有权威定义，别自己造

**CoverageBench: Evaluating Information Coverage Across Tasks and Domains**
（Samuel, Yates, Lawrie, Adriaanse, Van Durme, Yang @ JHU HLTCOE + Soboroff @ NIST；**SIGIR'26**；arXiv:2603.20034）

- **覆盖度定义**：把信息需求拆成离散 **nuggets**（子话题 / summary content units），度量结果集覆盖了多少 nuggets。
- **指标（都是现成的，论文不发明新指标）**：
  - **α-nDCG@20**（Clarke 2008）—— 对重复子话题折扣，**惩罚冗余**
  - **StRecall@20**（Zhai 2003）—— top-k 覆盖的**不同子话题比例**
  - **nDCG@20** —— 作为对照的相关性指标
  - （多答案检索那条线则用 **MRecall@k**，全有或全无的集合召回）
- **核心发现：高相关性 ≠ 高覆盖度**（论文最重要的一类证据）：
  - **NeuCLIR**：重排后 nDCG 几乎不动（0.821 → 0.819），但 **StRecall 从 0.836 掉到 0.786**；
  - **CRUX-MultiNews**：最佳 nDCG 的配置 ≠ 最佳 StRecall 的配置；
  - **CAsT**：nDCG 跨 0.323~0.651，但所有配置的 StRecall 都卡在 **≈0.55**（覆盖天花板）。
  - 论点："**高召回是覆盖度的充分条件，而非必要条件**"。
- 规模：**7 个数据集、334 个话题**，平均 nugget 数 6.1（CAsT）~ 29.7（Fair Ranking）；HF: `hltcoe/coveragebench`。

→ **这独立验证了我们上个月的发现**："CE（pointwise，永远把语义最像的排前面）在**覆盖率**上反而比融合差
（交付 20 篇：21% vs 27%）" —— CoverageBench 的说法就是"**为相关性优化 → 系统性丢覆盖度**"。
→ **行动**：把我们的 `coverage@N` 换成 **StRecall@N / MRecall@N**，冗余用 **α-nDCG**。可直接对标，也可直接用它的 7 个数据集做外部验证。

## 3. 证据/引用正确性：有标准指标（ALCE）

**ALCE: Enabling Large Language Models to Generate Text with Citations**（Gao, Yen, Yu, Chen；Princeton；EMNLP 2023；arXiv:2305.14627）

- **citation recall**：逐 statement，用 NLI 模型 **TRUE**（`google/t5_xxl_true_nli_mixture`）判定
  "被引 passage **拼接后**是否蕴含该 statement"（+ 至少有一个引用）。整篇取平均。
- **citation precision**：逐引用，判"**irrelevant**"= (a) 它单独不蕴含该 statement **且** (b) 去掉它剩下的仍能蕴含 → 其余记 1。
- **QAMPARI 子集**：因答案是列表，**每个实体算一条 statement**，逐答案套同一套 NLI 流程。
- **正确性**：集合 P/R + 一个实用调整 **recall-5**（预测里含 ≥5 个正确答案即记 recall=100%，因为用户通常只想看几个例子）。
- **自动指标的噪声底（我们评测时要交代的）**：与人工对比，recall 判定准确率 85.1%、precision 77.6%；
  Cohen's kappa：recall 0.698（substantial）、precision 0.525（moderate）。
- **⚠️ 明确的捷径警告**：直接把 top-1 passage 当答案并自引，**引用分接近满分（99.4/98.7）**，但 fluency/correctness 崩
  → **引用分必须与正确性合并看**。（我们在 fullctx 上做的"引用灌水 3.90×"探针，就是同一类问题的另一个版本。）

→ **行动**：产品要的"逐篇证据"用 **ALCE 式 citation recall/precision** 评测（照抄流程，不自己设计），
并且**固定要报"引用分 + 集合 P/R 一起"**，否则会被捷径刷分。

## 4. 工程侧：这就是系统综述的"文献筛选（screening）"

| 事实 | 出处 |
|---|---|
| **"给定一批文献，逐篇判定是否满足某条纳入标准"是系统综述的标准步骤** | 系统综述方法学 |
| ASReview / AiReview 等工具：**主动学习只负责排序，最终判定权留给人（oracle）**；明确**拒绝 LLM 全自动**，理由是幻觉与漏检 | ASReview 官方（asreview.nl），AiReview (arXiv:2504.04193) |
| 指标：**Recall / WSS@95%（Work Saved over Sampling，省了多少人工）/ ATD（发现耗时）**；用 Simulate 做离线评测 | ASReview 方法学（van de Schoot et al., Nature MI 2021） |
| PNAS 2024：LLM 适合做**预筛（prefiltering）** | PNAS 10.1073/pnas.2411962122 |
| **LLM 筛选实测：灵敏度可达 100%，但精度 <10%** | "Compact LLMs for title & abstract screening"（2026） |

→ **这是最重要的工程结论**：**"高召回 + 低精度"是这个任务族的既定常态**，工业界的回答是
**"AI 排序 + 人兜底"**，而不是"宣布哪几篇是全部"。
→ 我们测到的 P 0.49 / R 0.67（零 LLM）与之同源（我们的精度其实还好，但**结论方向一致**）。
→ **行动（产品交互）**：不要宣称"这个方向我都看过了"；应是 **"候选 N 篇 + 逐篇证据 + 一键继续扫/扩大"**。

## 5. 产品侧：形态已被做出来

| 产品 | 对应我们的哪一步 |
|---|---|
| **Elicit「columns」**：对一批论文"为每个想抽的数据点建一列" | **逐篇抽取（我们的 map 步）** |
| **NotebookLM**：用户自带语料 → 问"哪些来源提到 X" → 内联块级引用 | **整体形态（最接近我们的场景）** |
| **PaperQA2**：整箱 PDF 问答 + 引用溯源（证据收集 + 逐篇判定） | **block 级证据 + 逐篇判定** |

→ 说明**形态不新**；我们的差异化只能落在 **"覆盖度保证 + 评测"** 上，而不是形态。

## 6. 定位结论：我们改什么、不做什么

### 该改（采现成，不造轮子）
1. **指标全套替换**：
   - 覆盖/完备 → **MRecall@k**（JPR）/ **StRecall@k**（CoverageBench）
   - 冗余 → **α-nDCG**
   - 证据 → **ALCE 式 citation recall / precision**（NLI 判定）
   - 判定 → **集合 P/R + recall-5**（ALCE 对 QAMPARI 的实用调整）
2. **方法采现成**：我们的"每篇保底"= **round-robin / quota**（AMER 已用）；覆盖导向重排用 **MMR / DPP / LLM-as-MMR**（我们还没测 MMR）；
   多查询分解 = AMER 的多嵌入 / 查询扩展。**JPR 的"联合打分"是更进一步的选项（成本高）**。
3. **产品口径按筛选领域的教训**：给候选 + 证据 + "继续扫"，**不做完备性宣称**。

### 不该做
- ❌ 不要自己发明覆盖指标（`coverage@N` → 换 StRecall/MRecall）
- ❌ 不要再花力气论证"排序式 top-k 不适合枚举任务"（JPR 2021 已论证，我们只需引用）
- ❌ 不要把"引用分"单独当交付质量（ALCE 的捷径警告）

### 我们的差异化（可以讲的）
1. **语料形态不同**：文献在**开放域大语料（Wikipedia 21M 段落）**上做多答案检索；我们做的是
   **用户自带的一小批论文（N=20）+ facet 存在性判定 + 完备性声明** —— 这个组合**没有公开评测**。
2. **端到端串联**：别人评"检索/答案"；我们**从帮读（RAG-2 旧资产）→ 集合问答**串成产品链，且能复用 RAG-1/XLING/归属校验。
3. **两个我们已量到、文献没细说的坑**：
   - **同源偏袒 19pt**（用锚点原词检索得 0.837，改写查询只有 0.647）→ 评测陷阱，必须交代查询来源；
   - **块级证据召回只有 9%~46%**（每篇取 1~12 块）→ "篇级判对"与"证据给全"是两件事。
4. **AMER 指出的基准缺陷**（gold 文档彼此太像 → 多样性评测不足）：我们的题集正好可补，但**要先确认我们的 gold 不是也太像**。

## 7. 下一步建议（按"少走弯路"排序）

| 序 | 做什么 | 为什么 |
|---|---|---|
| **1** | **把已有 105 条数据换成标准指标重算**（MRecall@k / StRecall@k / α-nDCG + ALCE 式引用判定） | 让我们的数字**能和文献对标**（JPR 的 MRecall、CoverageBench 的 StRecall）；否则自造指标没人认 |
| **2** | 补测 **MMR / 轮询（round-robin）** 与我们的"每篇保底"对照；补 **多查询分解**（AMER 路线，最便宜的近似 = facet 的多侧面改写） | 这些是已被验证的方向，直接拿来对比 |
| **3** | **真值人工抽检**（ALCE 的 85% 说明自动判定可行，但先要有人工基准） | 目前所有数字都建在未验证的词面真值上 |
| **4** | 用 **CoverageBench（`hltcoe/coveragebench`）** 做一次外部验证 | 有现成数据 + 代码 + 基线，可低成本证明"我们的覆盖导向重排有增益" |
| 5 | 产品交互改口径：候选 + 证据 + 继续扫 | 与筛选领域的一致做法对齐 |
