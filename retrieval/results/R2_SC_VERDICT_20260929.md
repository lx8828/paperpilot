# R2｜S/C 分流裁决：检索线该不该独立出来

日期：2026-09-29 ｜ 脚本：`retrieval/tmp/_ctx_limit.py`、`_r2_fullread.py`、`_m1_set_ab.py`、`_m1_set_diag2.py`、`_sc_verdict.py`

## 0. 问题

生产线语料恒为 **5 篇（≈48k token）**，这类题已知**全走 `fullctx` 全上下文直读可行**（`read_full.py`：M1 直读 30/50 vs 检索管线 20/50，且 4.3s vs 22.1s、¥0.006 vs ¥0.026）。
那么"重构后的 RAG-2 / 集合问答线"**只有在语料超过上下文时才有意义** → 它接不上生产管线 → **该不该单独成线？**

判据用 `S/C = 语料 token / 上下文预算`，所以先测 **C**。

## 1. 上下文预算实测（`_ctx_limit.py`）

| 塞入 | 结果 |
|---|---|
| 8k / 32k / 64k token | ✅ |
| **810,141 token** | ✅ **API 接受**（14.5s） |

→ **deepseek-chat 实际可接受 ≈810k token**（远超常见宣称的 64k/128k）。
→ 所以 **R2 的 266k/簇塞得下** → 实验 1 是**真正的头对头**，不是"塞不下"。

⚠️ 边界：这是"API 接受"，不等于"模型真读到"。**行为侧证据**见实验 1 的 `touched=20.0/20` 与 `R=0.908`（266k 范围内注意力确实覆盖）。未做 needle-in-haystack 严格验证。

## 2. 实验 1｜R2 语料 20 篇/簇（S/C ≈ 2.03）整档直读 vs 局部检索+判定

同真值配对 **n=30**（真值 = `gold_recalib` 校准后；指标 = 篇级集合 P/R/F1）。

| 臂 | 输入 | P | R | **F1** |
|---|---|---|---|---|
| **A 整档直读** | 20 篇**全文**，一次调用（**305,917 tok**/题） | 0.709 | **0.908** | **0.773** |
| **B 逐篇局部检索 + 判定** | 每篇**自己的** top-6 块（≈**24k** tok/题，20 次小调用） | **0.879** | 0.801 | **0.817** |
| **C 篇级检索 top-10（无判定）** | 只给篇名序，无判定 | 0.457 | 0.851 | 0.539 |

| 配对差 | Δ | 95% CI | P(Δ>0) | 判定 |
|---|---|---|---|---|
| **B − A**（局部检索+判定的增益） | **+0.044** | [−0.049, +0.149] | 0.809 | **不显著** |
| B − C（判定层的增益） | **+0.278** | [+0.178, +0.382] | 1.000 | 显著 |
| A − C（整档相对篇级检索） | **+0.233** | [+0.166, +0.306] | 1.000 | 显著 |

**读数**：
1. **整档直读在 266k 上完全可行**（`touched=20/20`、R 0.908 全表最高）→ **"超上下文"不是这条线的门槛**。
2. 但整档直读**精度差**（P 0.709），交付篇数 **7.90 vs gold 5.87 = 1.35×** → "全塞"会让模型**多列**。
3. **逐篇局部检索 + 判定**:F1 略高（+4.4pt，**不显著**），但 **token 省 11 倍**、精度高 17pt。
4. **C 臂说明**：篇级检索（哪几篇相关）**单独无用**（F1 0.539）——**检索的收益必须由"判定"兑现**。

→ **结论：在 S/C≈2，检索+判定 相对整档直读是"不劣 + 省 11× token + 精度更高"**，而非"必需"。

## 3. 实验 2｜生产 5 篇（S/C ≈ 0.37）M1 50 题：fullctx vs set

对照臂 = **同题**（`fullctx_m1all_group{1..5}.json`，50 道 M1）；判分 = `run_multi_qa.score_answer`。

| 臂 | 说明 | `ok_strict` |
|---|---|---|
| **fullctx 全上下文直读** | 1 次调用，全文 47k tok | **30/50 = 60.0%** |
| **S `shipped`**（现行 `set_judge.render`） | 篇名 + ≤80 字理由 | **6~7/50 ≈ 12~14%** |
| **Y** 判定当路由 + yes 篇原文 | 同判定，答案带内容 | **34/50 = 68.0%** |
| **A** 全部 5 篇原文倾倒（**不靠判定**） | 无判定、无成稿 | **44/50 = 88.0%** ← ⚠️ |

### 3.1 为什么 `set` 只有 12~14%——**不是判定错，是题形是复合题**

诊断（`_m1_set_diag.py`）逐题对照：

| 题形 | 题数 | fullctx | set |
|---|---|---|---|
| 集合筛选 + 枚举 | 19 | 11 | 2 |
| 集合筛选 | 14 | 8 | 1 |
| 跨篇对比/枚举 | 11 | 7 | 2 |
| 其他 | 6 | 4 | 1 |

典型失败（`set` **篇选对了**，但答案里没有锚点）：

| qid | set 交付 | 缺失锚点 | 题面 |
|---|---|---|---|
| `G3-M1-9` | **5/5** | `unweighted tree`、`Memory Self-Evolution` | 哪些篇做了组件消融？**各自消融掉的是什么**？ |
| `G4-M1-6` | **5/5** | `47,000`、`23.38%` | 报告了哪些关键数字？**给出至少两篇的数字** |
| `G3-M1-10` | **5/5** | `32.8%`、`buffered writing` | 哪些篇报告了开销控制手段？**各自的手段是什么** |

→ **M1 = 「集合筛选」∧「内容枚举」的复合题**。`set_judge` 只答前半（"哪几篇"），**不答后半**（"各自是什么"）→ 锚点全缺。

### 3.2 度量陷阱（**重要**）

**A 臂 = 88%**：不做判定、不做成稿，只把检索块原文倒进答案 → 锚点**必然出现**。
→ **`ok_strict` 在 M1 上度量的是"信息出现率"，不是"答案质量"** → **不能用来比较交付形态**。
→ 但 **fullctx 的 60% 是诚实的**（LLM 成稿、不倾倒），该数可用。

### 3.3 补丁：`extract`（逐篇内容抽取）→ **14% 抬到 34%，仍不及 fullctx**

实现：`set_judge.SYS_SET_EXTRACT`（判定之外多要 `extract` = 该篇在本题上的具体内容，
数字/专名逐字照抄）；开关 `PAPERPILOT_SET_EXTRACT`（**默认关**，保持旧行为）。

| 臂（同题 50 道 M1） | `ok_strict` |
|---|---|
| `fullctx` 全上下文直读（存档） | **30/50 = 60.0%** |
| RAG-2 检索管线（既有实测，`read_full.py`） | 20/50 = 40.0% |
| **E `extract` 逐篇判定 + 逐篇内容（新补）** | **17/50 = 34.0%** |
| S `shipped` 仅判定·无内容（原） | 7/50 = 14.0% |
| Y 判定当路由 + yes 篇原文 | 34/50 = 68.0% |
| A 全部 5 篇原文倾倒（假阳性上界） | 44/50 = 88.0% |

**读数**：
1. `extract` **确实补上了内容**（14% → 34%，50/50 题都产出 extract），抽取质量正常
   （例：`最大相对提升为39.5%，对应数字0.0484与0.0347（Beauty NDCG@10）`）—— **不是倒原文**。
2. **但只到 34%，远低于 fullctx 60%**。失败清单显示缺的仍是**具体术语**
   （`Gemini`、`Disperse`、`HotpotQA`、`topic documents`、`fact revision`、`22k+ tools`…）。
3. **根因**：M1 的答案需求是**长文综合写作**（每篇多个要点 + 跨篇对比 + 复述"各自做法"），
   而"每篇一句 ≤60 字"的抽取**容量不足**。→ 这不是开关能解决的，是**题形与交付形态的错配**。
4. **三条"成稿"路线全部低于 fullctx**：fullctx **60%** > RAG-2 40% > set+extract 34% > set 14%。

### 3.4 回归：`extract` 会**轻微改变集合判定**（不能全局开）

在 R2 的**纯集合题**（30 真值，`extract` 在此无用）上同流程对照：

| 指标 | `SYS_SET`（基线） | `SYS_SET_EXTRACT` | Δ（95% CI） |
|---|---|---|---|
| 集合 P | **0.879** | 0.807 | **−0.072** [−0.139, −0.021] ⚠️ |
| 集合 R | 0.801 | 0.818 | +0.017 [+0.004, +0.032] |
| **集合 F1** | **0.817** | 0.796 | −0.021 [−0.052, +0.006]（不显著） |
| 交付篇数 | 5.23 | 5.87 | +0.63（gold 5.87） |

→ 多要一个字段让判官**更宽松**（多交付 0.63 篇）：**F1 不显著降**，但 **precision 显著降 7.2pt**。
→ **`extract` 必须按题形开关**（复合题开、纯集合题关），**不能全局打开**。

### 3.5 代码层接线（回答"两条线会不会接到一起"）

`answer_set` **已经在图里**（`graph/qa_graph_v3.py` L80/L88），由三点开关选择：

```
PAPERPILOT_QA_READER = fullctx（默认）| retrieval（RAG-2）| set（集合问答）
```

→ **数据/评测层完全不重叠**（R2 = 20 篇/簇；生产 = 5 篇/组，题与真值均不同）；
→ **代码层已通但默认不切**，且本页实测**证明不该切**（5 篇上 60% > 40% > 34% > 14%）。

## 4. S/C 阶梯：检索线的**价值起点**

| 设定 | ≈token | S/C | 实测 | 判定 |
|---|---|---|---|---|
| **生产 5 篇** | 48,000 | **0.37** | fullctx 30/50 **>** 检索线 20/50 | ❌ 检索不值 |
| QAMPARI 128k | 105,322 | 0.80 | 直读 0.700 **==** 检索 0.700 | ➖ 打平 |
| **R2 20 篇/簇** | 266,423 | **2.03** | 整档直读 0.773 **<** 局部检索+判定 0.817（省 11×） | ✅ **检索值** |
| QAMPARI 1m | 844,484 | 6.44 | 直读崩（24% 上下文只拿 3/5） | ✅✅ 必需 |

→ **价值起点落在 S/C ≈ 0.8 ~ 2.0 之间**（**不是 S/C = 1**，更不是"塞不下"）。
→ 生产 5 篇（0.37）在价值区**之外** ⇒ **检索线该独立**。
→ 但独立的**理由不是"塞不下"**（实测能塞 810k），而是：**语料大到"逐篇局部化"才划算**。

## 5. 架构裁决

| 组件 | 去留 | 依据 |
|---|---|---|
| `fullctx` 全上下文直读 | ✅ **生产默认不变** | 5 篇上 60% > RAG-2 40% > set+extract 34% > set 14% |
| **RAG-2 检索管线** | ⛔ **生产不用**；**独立成线** | 5 篇上 20/50；S/C ≥ 2 才有净收益 |
| **`set_judge` 逐篇判定** | ⛔ **不做生产 reader**；留在独立线 | M1 复合题补上 `extract` 也只到 34%；且 M1 **无篇级真值**，判定质量在此**不可测** |
| 独立线服务对象 | **S/C ≳ 1~2**（20 篇以上 / 开放域） | 实验 1（+4.4pt 不显著但省 11×、精度 +17pt） |

**代码层接线**：`answer_set` **已在图里**，由 `PAPERPILOT_QA_READER` 三点开关选
（`fullctx` 默认 / `retrieval` / `set`）→ **代码已通、默认不切**，且实测**证明不该切**。

**`extract` 缺口已补，但结论不变**（见 §3.3）：
```
set_judge（筛选：哪几篇）  →  ✅ extract（逐篇内容，已实现，默认关）  →  ✅ render 带上
      ✅ 已有                         ✅ 本次补上                         ✅ 已改
```
→ 补上后 **14% → 34%**，**仍不及 fullctx 60%** → 缺口不是"少个字段"，
而是 **M1 要"长文综合写作"，`set` 的交付形态（逐篇一句话）容量不够**。
→ 另：`extract` 让判官更宽松（R2 precision **显著 −7.2pt**）→ **必须按题形开关，不能全局开**。

## 6. 诚实边界

1. **实验 1 的 B−A 不显著**（+0.044，CI 跨 0）→ 只能说"不劣 + 更省"，**不能说"更准"**。
2. **实验 2 的 A 臂是假阳性上界** → `ok_strict` 不能比较交付形态；Y 的 68% 也可能偏高。
3. **M1 无篇级真值** → 判定质量在生产题形上**未被评测**（只有 R2 的 30 真值可测）。
4. 上下文上限 810k 是**单模型单时刻的 API 接受**，未做 needle 严格验证。
5. `S/C` 的"C"取的是**单次调用预算**，未计入 prompt 缓存（缓存命中可等效放大有效预算）。
6. §3.3 的 E 臂用了 **`SYS_SET_EXTRACT` 单版提示**（`extract` ≤60 字），未做容量调参
   → **34% 是这一版的下界，不是"加抽取"的上界**；但 A（88%）说明"加量"会滑向倾倒。
7. §3.4 的回归只在 **R2 的 30 真值**上做，且为**单次运行**（`temperature=0` 仍有轻微非确定性）。
