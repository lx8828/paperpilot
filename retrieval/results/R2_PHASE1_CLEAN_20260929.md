# R2｜Phase1 复跑（干净口径）：多查询 / 轮询聚合 / MMR 值不值

日期：2026-09-29 ｜ 语料：r2dev 3 簇 × 20 篇 ｜ 真值：35 个 ｜ 打分：`dense`（bge-m3，1000 字块）

## 0. 为什么要复跑

第一版 `_r2_phase1.py` 的查询集是 `qs = [f"{zh} {anchor}"] + subqueries`。
`anchor`（英文锚点词）**63% 与 gold 正则同词**（`R2_LEAK_AUDIT_20260929.md`）→ **首查询有泄露**。
本复跑把查询集换成 **`[zh] + subqueries`（clean）** 与 **`[zh] + 净化子查询`（desens，最严）**，
并保留旧版 `contam` 作对照。

## 1. 子查询本身与 gold 正则的重合：**30.9%**

`subqueries.json` 是 **LLM 从中文题面**生成的（输入只有 `论断：{zh}`），不存在"照 gold 反推"。

| facet | 与 gold 正则重合 token 占比 | 重合词 |
|---|---|---|
| （16 个 facet 平均） | **30.9%** | — |

→ `消融实验 → ablation` 这类属于**语言必然**（该概念只有这一个英文词），不是我们按 gold 反推。
→ 仍用 **`desens` 臂（删掉重合词）** 给出**下界**。

## 4. 结论

1. **多查询（`mq_max`）在干净口径下仍有增益，但不显著**
   `StRecall@10` **+0.043**、集合 F1 **+0.032**（0.581 vs 0.549）、α-nDCG **+0.050**（0.847 vs 0.797）
   → 三个指标方向一致；但配对 CI 下界 −0.003 **贴 0** → **只能说"倾向于有增益，35 个真值不足以判定"**。
   → `desens` 臂仅掉 **2.2pt**（0.725 → 0.703）→ **增益大部分不是靠 gold 词**。

2. **★ MMR（覆盖导向重排）在篇级交付上【显著有害】**
   λ=0.5：`StRecall@10` **−0.059**，CI **全负**（[−0.102, −0.024]）；且随 λ 减小**单调变差**（0.681 → 0.654 → 0.622 → 0.626）。
   → 解释：本任务的 gold 篇**彼此相似**，MMR 的"多样性惩罚"恰好把**相似的 gold 篇互相推开** →
   与 CoverageBench 的"为相关性优化丢覆盖度"**方向相反**：这里是**为多样性优化丢了相关性**。
   → **这是本次复跑唯一【显著】的方法学结论。**

3. **轮询聚合（AMER round-robin）没有额外收益**：C ≈ B（0.717 vs 0.725，差异不显著）。
   → 与 `R2_LEAK_L2` 的结论一致：轮询的价值只在"**保证每篇被看过**"，不在提升排序质量。

4. **泄露对本实验的影响很小（±1pt）**
   A base：contam 0.671 → clean 0.681（**+0.011**）；k=5 反而 −0.034。
   → 原因：查询集是 `[首查询] + 3 条子查询`，**子查询稀释了首查询里 anchor 的作用**。
   → 而 `R2_LEAK_AUDIT` 测的是**单查询** `zh` vs `zh+anchor`（AUC +0.074）→ **两者并不矛盾**：
     **泄露藏在首查询里，影响大小取决于它是不是唯一查询。**

## 5. 边界

1. **n=35 个真值**，配对 bootstrap 的 CI 仍较宽 → 除 MMR 外的差异都**不能下结论**；要判定"多查询有用"需扩题或换更强设计（同一真值多次扰动）。
2. `desens` 只删重合**单词**、未做同义替换 → **0.703 是下界**，真实增益应高于它。
3. `random` 是 **200 次排列均值**；`oracle` 用了 gold → **仅作上界**。
4. `k=20` 未列：随机基线 `StRecall@20` 也 = 1.000（送全部 20 篇），**无信息量**。
5. 只测了 `dense`（bge-m3）一路；BM25 与融合路径未复跑。
