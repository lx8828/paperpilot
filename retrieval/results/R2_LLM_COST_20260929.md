# LLM 成本核算（2026-09-29）：**"全部用 LLM"不贵**

> **一句话**：逐篇 LLM 判定 ≈ **¥0.030/题**（100 题 ≈ ¥3）；QAMPARI 一次完整评测 ≈ **¥0.31**。
> **真正贵的不是"判定"，而是"把长语料塞进输入"**（1m 档全塞且**无缓存** = **¥0.90/题**，是判定的 30 倍）。
> 关键杠杆只有一个：**前缀缓存**（官方命中价 = 未命中的 **1/50**）。

## 4. 三条结论

1. **"全部用 LLM"不贵**：逐篇判定 **¥0.030/题**，与现有产品链路（¥0.026/题）同量级；
   一次 100 题标准评测 **¥0.31**。
2. **贵的不是判定，是"把长语料塞进输入"**：
   - 1m 档全塞**无缓存** = **¥0.90/题**（判定的 **30 倍**）
   - 1m 档全塞**有缓存** = ¥0.020/题（掉到 1/46）
   → **担心成本时，该担心的是"全塞 + 不命中缓存"，不是"逐篇判定"。**
3. **三个省钱杠杆（按效果排序）**：
   - **① 前缀缓存（50×）**：**语料/系统提示放 prompt 前面、问题放最后** —— 我们 fullctx 线已是这个做法；
   - **② 免费模型做初筛**：GLM-4-Flash / GLM-4.7-Flash **官方免费**，可承担"逐篇初筛"，DeepSeek 只做终判 → $0.030 → **¥0.013/题**；
   - **③ 只送检索到的块**（而非全文）：输入量差 20~300 倍。

⚠️ **方法学记录**：第一版测试把推理模型的 `max_tokens` 设成 30 → **思考吃光预算 → content 为空**，
被误判为"模型名不可用"。**推理模型（reasoner / 默认思考模式的 flash）必须给 1500+ token 预算。**

## 7. 诚实边界

1. **价格为 2026-09-29 抓取的官方页面**；官方保留调价权 → 换价只需改脚本 `PRICE`。
2. 表里的"命中 in"是**乐观假设**（同前缀跨题复用）；真实命中率取决于 prompt 组织方式（§4 杠杆①）。
   本机 fullctx 实测命中率曾达 **99%**，所以这个假设有依据，但**新链路必须实测命中率**。
3. GLM 免费政策由厂商定，可能变；"免费"是按当前公开口径。
4. **未计入本地 GPU 成本**（bge-m3 编码、NLI 已弃用）；单题编码是秒级、可忽略。
