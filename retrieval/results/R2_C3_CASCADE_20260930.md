## ⚠️ 先记一条方法论教训（我自己踩的）
第一版用 `setpf(o, gold, **k=50**)` 评两臂 → 跑出 **"ΔF1 = +0.000，完全一致"**。
**这是假的**：`k=50` = 全部篇数时 `o[:50]` 含**所有 50 篇** → setF1 退化成只反映 `|gold|`
（簇1 11/50→0.361、簇2 10/50→0.333、簇3 17/50→0.507，**三个数全对上**）。
→ 集合型输出的指标**必须用 P/R/F1**，不能拿"截断 k = 全集"的 setF1。

## ★★ 三条结论（两条是否定我上一轮的）

### 结论 1：❌ **"regex 命中直接判正"是错的**（更正上一轮建议②）
- V3 单看：省 16.5%，但 **F1 0.750 → 0.684（−0.066）** —— 它是**用精确率换召回**
  （P 0.780→0.597 掉得多，R 0.731→0.844 升得少）
- 且**去掉它反而更好**：同省 50% 时 **V2 0.578 > V1 0.529**
- → **不要**把 regex 当免费判正器。（上一轮我看到它 AUC 0.737 就推荐了 —— **判别力高 ≠ 阈值行为好**，
  这在**同领域高相似**的池内尤其明显。）

### 结论 2：⚠️ **NLI 粗筛省调用的代价不可忽略**（也弱化了上一轮的乐观）
| 省 | 最好 F1 | ΔF1 |
|---|---|---|
| 0% | 0.750 | — |
| 36% | 0.578 | **−0.172** |
| 50% | 0.578 | **−0.172** |
| 63% | 0.550 | −0.200 |

→ **省一半调用要掉 0.17 F1，掉的主要是召回**（R 0.731 → 0.458）。

### ★ 为什么与上一轮"gold 篇留存 99.1%"矛盾？—— 上一轮的指标是**必要不充分**
上一轮测的是"τ=0.1 时 gold 篇**有 ≥1 块存活**占 99.1%"。但这里发现：
**"有块存活" ≠ "判官会判正那块"**。
证据：**V0 全判（不筛任何块）的召回也只有 0.731** —— 即 27% 的 gold 篇在**逐块**判官下
**一块都判不正**。既然上限就是 0.731，任何筛除都会继续往下压 → R 掉到 0.458。
→ **教训：级联可行性不能只看"存活率"，必须看"存活块被判正的比例"**（上一轮漏了这一步）。

### 结论 3（★ 真正的省钱点，且与 NLI 无关）
既然 **V0 的召回只有 0.731**，说明**"逐块判"本身就是个弱协议**。
而生产协议是 **"每篇 1 次、输入 ≈4,205 字符窗口"**（A+B 双判官）→ **k=20 篇 = 20 次调用/题**，
**比逐块 253 次/题省 92%**。

| 协议 | 调用/题 | 备注 |
|---|---|---|
| 逐块判（本脚本臂①） | **253** | R 仅 0.731 |
| **窗口判（现有生产协议）** | **20**（k=20） | 产出 `gold_final3` 的那个；**基准更省** |

→ **所以 C3 本来就不贵**：全量 28 题 = **560 次调用 ≈ ¥3**（不是 6,916 次）。
NLI 在此**没有多少省调用空间可占**（能省的 92% 已被"窗口化"拿走）。

## 边界
1. **仅 3 个 facet**（每簇 1 个）→ 噪声大，**只判方向**，别当定论。
2. 逐块协议 = **单判官**（`PAPERPILOT_LLM`），gold = **双判官 + 第三轮** → 与 gold 的差距含口径混杂。
3. 判官输入 = **整块（中位 1,794 字符）**，未做"块切句"→ 这与 ALCE 句级口径不同。
4. τ 在**本小样**上选；`R2_C3_LABELS.csv` 只覆盖池内块。
5. 未测：window 协议下 NLI 缩窗的 token 收益；NLI 作**独立召回**预筛的效果。
6. 158 NaN/ERR：本次 **ERR = 0**（3 facet 全部成功）。
